## 新增 `npm run models:regions`（scripts/emit-regions.mjs）

读模型里真实的零件名，生成可直接粘贴的 `regions` 配置骨架。解决「用户改了分区就得找我们改配置」这件事。

- 只读不写：不碰源码，粘贴由人确认（顺便当一次人工复核）
- 沿用已有中文名 / 可贴设置；新零件标 `TODO 中文名`
- **按商品分开索引命名表**，先查本商品再借全局，借用时注释标出来源
  （`body` 在茶杯是「杯身外壁（可贴）」、花瓶是「瓶身」、冰箱贴是「背面与侧边（保留）」，
  初版用全局 union 索引导致语义串位，已修）
- 常量名沿用源码里现有的（`CUP_REGIONS` 等，同类商品共用），粘回去不用改 `regions:` 引用
- 对齐用的空格加在引号**外**，否则会变成字符串内容（中文名会多一个尾随空格）

**做过「粘贴即生效」实测**：把脚本输出替换进 `modelPresets.ts` → `tsc` exit 0、`eslint` 0 error、
`models:verify` 10/10 全部 `[精确匹配]`，随后还原。

## 定下部位命名规范：`<商品前缀>_<部位>`

用户问「有个茶杯，我分把手和杯体，想命名成 tea handle / cup body，你帮我定一套命名」。
定稿：**全小写 + 下划线，纯英文，格式 `<商品前缀>_<部位>`**。
前缀按商品固定：`cup_` / `vase_` / `magnet_` / `bag_` / `fan_`。

| 商品 | 可贴图 | 保留 |
| --- | --- | --- |
| 茶杯 | `cup_body` 杯身外壁、`cup_handle` 把手 | `cup_inner` 杯口与内壁（optional） |
| 花瓶 | `vase_body` 瓶身、`vase_neck` 瓶颈 | — |
| 冰箱贴 | `magnet_face` 正面贴图区 | `magnet_body` 背面与侧边 |
| 帆布包 | `bag_front` 正面、`bag_back` 背面 | `bag_body` 侧边与提手 |
| 扇子 | `fan_face` 扇面 | `fan_handle` 扇骨与扇柄 |

**意图**：带前缀是为了 `mug_a.glb` / `mug_b.glb` 这类同名部位在配置文件里可读、可 grep；
用户原来想的 `cup body`（带空格）也认 —— 见下。

### 配套改动

1. `regions.ts` 匹配**从 3 级扩到 4 级**，新增「去全部分隔符后一致」
   （`CupBody` / `cup body` / `cup-body` 都能命中配置里的 `cup_body`）。
   排序理由：3 是「整体相同只是分隔符不同」，可信度高于 4 的「恰好包含这个词」。
2. `RegionConfig` 新增 `optional?: boolean`：模型里可以没这个部位，自检不报「缺部位」。
   用来兼容「不同人拆的粗细不同」（茶杯有人不拆内壁）。
   `RegionReport` 新增 `absentOptional` 把这类缺失从 `missing` 分流。
3. `modelPresets.ts` 每个部位写**「带前缀 + 不带前缀」双别名**（`match: ['cup_body','body']`），
   所以带不带前缀都能**精确**（优先级 1）命中，不会掉到模糊匹配。
4. **茶杯把手从「保留」改成「可贴」**（用户想要点把手就贴把手）。
   顺带说明「可贴 / 保留」只是配置里 `paintable` 一个字段，改 `false`→`true` 即可换。
5. `make-placeholder-models.mjs` 占位模型零件名同步改成带前缀，
   保证 **文档 ↔ 配置表 ↔ 模型对象名** 三处完全一致。
6. `emit-regions.mjs` 修了两处信息丢失：初版会砍掉 `match` 双别名与 `optional` 标记，
   粘回等于自毁兼容性。修后实测「粘贴即生效」（tsc 0 错 / eslint 0 错 / verify 10/10）。

### 顺手修掉的两个真 UI bug

- **`RegionPicker` 贴完一处后不出现**：`AiPanel`/`UploadPanel` 里 `<RegionPicker />` 被包在
  `{waitingForPick && ...}` 里，贴成功后 status 变 `applied` 就整个消失。
  改成移出条件块 + 加 `source` prop 区分来源（否则两个面板会重复渲染），
  `textureStudio.paintRegion` 支持「沿用最近一张图接着贴别的部位」。
- **画面中部一竖排乱码**：DOM 查明是 `.scene-error-badge`（环境贴图加载失败提示），
  矩形 42×968 —— drei `<Html>` 容器按内容收缩，中文被压成竖排。
  加 `width: max-content; min-width: 180px;` 后变 289×104。

### 严重问题：UI 高亮被烘进导出的 GLB

**现象**：e2e 全绿，但截图里橙色总出现在「最新贴的那块」。
**根因**：`BodyTintedConfigurator` 的选中高亮（`color` 向 `#ffeb3b` 插值 + `emissive` 设 `#ffaa00`）
直接写进 `material.color` / `material.emissive`，`GLTFExporter` 原样导出。
**铁证**：落盘的 GLB 里 `cup_body` 的 `baseColorFactor=[1.13,1.07,0.795,1]`、`emissiveFactor=[1,0.4,0]`，
原始模型是 `[1,1,1]`。
**修法**（这条要长期记住）：
- 彻底删掉此前「借用高亮」的 `registerHighlighter` 整套接线
  （`textureStudio` / `Scene` / `Configurator` / 两个 Configurator 的 prop 全清）；
- `surfacePainter.ts` 新增 `CLEAN_COLOR_KEY = '__cleanColor'` 与 `stripUiTint(root)`，
  两个 Configurator 在改色时把干净色记录进 `material.userData`，
  `ExportPanel.buildGlb` 在 `exporter.parse` 前后 `stripUiTint` / 还原（`finally`）。

**教训**：只要「UI 状态」和「材质属性」共用同一个字段（`material.color`），
导出前就必须清洗。以后再加任何高亮效果，一律走 `userData` / 独立字段，不要动 `material.color`。
