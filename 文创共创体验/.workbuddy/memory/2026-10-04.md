### 新增 `--extract-region`（`scripts/fix-model.mjs` 第三种拆分方式）

按「朝向 `axis`/`cos` + 包围盒归一化 `x/y/z` 区间」圈一块；配套 `--rename` 给剩下的那块改名。

```bash
npm run models:fix -- "文创商品模型/bag_a.glb" --out public/models/products/bag_a.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.7;y=0~0.53;z=0.5~1" \
  --rename "node_0=bag_body"
```

结果：`bag_front` 5822 面（可贴）、`bag_body` 47224 面（保留）；输出 1510 KB。

### 三个必须做对的实现点（都是踩出来的）

1. **平面真裁剪（Sutherland–Hodgman），不要整块丢三角形** —— 整块丢会让边界由三角形边决定，
   屏幕上约 4px 锯齿（像被撕开）；切开是一条精确直线。裁剪时 pos/nrm/uv 一起线性插值。
2. **顶点去重** —— 原顶点用 `v<索引>`、交点用 `e<平面id>_<排序后的两端点 key>`。
   不去重时顶点数撑成「三角形数×3」，文件大了一倍多（800KB+ → 实测）。
3. **★ 补集按凸块分解** —— 第 i 块 = 满足前 i 个平面、但在第 i 个平面外侧。
   用「所有平面取反求交」是错的（那是求对面那个盒子），实测 `bag_body` 只剩 22083 面（应 47000+）。

参数从数据估：先写探针沿 Y 分层统计跨度与正面面积占比，发现 `y>0.66` 后正面占比骤降（折边内壁不朝观众）
→ 定 `y=0~0.53`；只按 `nz>0.7` 会抓到背面外翻的部分 → 加 `z=0.5~1` 才干净。

主循环要**优先取 `group.geometry`**，否则串联多个拆分开关时前一步的几何会丢。

### 帆布质感（`src/three/finish.ts`）

`roughness 0.95` + `metalness 0` + `clearcoat 0` + `sheen 1`/`sheenRoughness 0.85` + `envMapIntensity 0.55`
+ **程序生成织纹法线贴图** `weaveNormalMap()`：128×128 高度场，瓦片内 8×8 根线做平纹织法
（`(tx+ty)%2` 决定经纬谁在上），余弦截面 → 中心差分算法线（索引环绕取模，瓦片无缝）。
参数 `repeat 8` / `normalScale 0.8`（实测 0.02/0.09 完全看不见）。

**用 `normalMap` 不用 `bumpMap`**：① bump 强度依赖屏幕空间 UV 导数，拉远自己消失；
② 导出时 bumpMap 只能写非标 `EXT_materials_bump`，normalMap 是 glTF 核心 `normalTexture`。
`DataTexture` 默认最近邻 + 不生成 mipmap → 必须设 `LinearFilter`/`LinearMipmapLinearFilter`/`generateMipmaps`。

## 追加：帆布包背面也能贴，且正反两面可各贴一张不同的图

用户新要求：「刚刚整个帆布包的背面也可以贴，并且两面可以选择不同的贴图」。

### 结论：功能层本来就支持，缺的只是「背面是不是独立部位」

读 `src/state/textureStudio.tsx` 确认：`paint()` **每次贴图都 `loadTexture()` 新建一张贴图实例**，
并把 `{surface, targets, texture, uv}` 压进 `liveStackRef`。所以
「上传图 A 点正面 → 上传图 B 点背面」天然得到两张不同的图案，**先贴的那张不会被顶掉**。
反而是「每个部位共用一个全局贴图」才会出问题 —— 现在的实现是对的，不要改回去。

### 模型侧：`--extract-region` 串联两条，正反各圈一块

```bash
npm run models:fix -- "../文创商品模型/bag_a.glb" --out public/models/products/bag_a.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.7;y=0~0.53;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.7;y=0~0.53;z=0~0.5" \
  --rename "node_0=bag_body"
```

→ `bag_front` 5822 面 / `bag_back` 4548 面（都可贴）/ `bag_body` 47016 面（侧边与提手，保留）；
输出 1706.1 KB。

**关键认知**：这个模型是**闭合壳体**（有内表面）。所以沿 Z 从中间切一刀正好分开两块外壁 ——
正面外壁在 z 后半、法向 `+z`；背面外壁在 z 前半、法向 `-z`；两面各自的内表面朝向恰好相反，
被 `cos` 和 `z` 区间同时挡掉。用探针脚本先量了朝向分布（`nz>=0.7` 占 34.3% 面积、
`nz<=-0.7` 占 34.4%，y 分层完全镜像）才敢下参数。

**串联的注意点**：`x/y/z` 是相对**当次输入几何自己的包围盒**归一化的。第二条以第一条的补集为输入，
其包围盒是 `0.678 × 1.043 × 0.279`（z 只比原来的 0.286 小一点 —— 因为补集里含了正面的内表面，
把 z 撑回去了），所以 `z=0~0.5` 的切线正好落在同一个位置。

### 先量截面：圆 vs 方（这次最关键的前置动作）

拆之前先写了个**截面探针**扫一圈半径（后固化成 `npm run models:section`）：

| 模型 | 中段截面半径（绕一圈） | 判定 |
| --- | --- | --- |
| `holder_a` | 恒定 0.337~0.339 | **正圆**（回转体），柱面展开等比 |
| `holder_b` | 0.319（面心）↔ 0.420（角），**每 90° 循环** | **方形带圆角**，主法向集中在 ±X/±Z |

反解圆角半径：方截面半宽 a、圆角 R 时 `r_max = (a−R)·√2 + R` → R≈0.075~0.084（≈半宽的 23~24%）。
结论是**「只贴外壁」的摘法照用、一条命令都不用改** —— 判据是法向 / 朝向，与截面形状无关：
四个面法向朝 ±X/±Z、内腔面法向朝心（面心 `radialDot=−1`、圆角处仍 < −0.707），
`--extract-inner` 一样摘得干净；口沿那圈方环是朝上的水平面，照旧留在外壁一侧。

## 把「复跑全表」做成一条命令：`npm run models:regress`

`55-全商品验证矩阵.png` 那张表一页就有 15 个格子，每个格子是一条命令 —— 手敲必漏。

**关键设计（不这么做就会变成「看着在跑、其实漏跑」的假绿灯）：**

1. **商品清单只留一份**。给三个 e2e 脚本加 `--list`，把各自 `CASES` / `SAMPLE_PARTS` 的键以
   JSON（`[{id,label}]`）吐出来，runner 现拉现用 —— **加了商品不用改 runner**。

   runner 还反向检查「只在 B 清单里、不在 A 清单里」的商品并打警告。
2. **产物目录可覆盖**（`E2E_OUT_DIR`）：回归一跑十几张图，默认落 `%TEMP%/wb-regress-<时间戳>`，

4. 其它开关：`--model holder_b` 只跑一个商品、`--only paint,export` 只跑某几步、`--list` 只看计划。

## 接两个花瓶：`vase_a`（圆肚）/ `vase_b`（细颈）

### ★ 关键发现：底部那刀 `y` 不能照抄笔筒

先按笔筒参数（`y=0~0.06`）dry 跑，结果 `vase_bottom` 报「**2 块互不相连的面**」、
块中心还偏离中轴 0.49（看着像 bug）。于是写了**分层探针**（按高度分层列面数 / 半径 / 朝向），
一看就清楚了：

- 模型经 `models:fix` **烘焙节点变换后整体平移过**，中轴在 `(0.369, -0.329)` ——
  块中心的「偏移」是假象，不是 bug。
- **花瓶的底是两级的**：外圈一圈朝下的环 + 中心一块位置最低的底盘，两块几何上互不相连、
  分布在 5%~11% 高度这段。`0.06` 那条切面**正好切在它中间** → 半个凹底留在 `vase_side`，
  贴图会贴到瓶底看不见的凹面。**抬到 `y=0~0.12` 就整个摘干净**（vase_a 2399 → 4644 面）。
- **AI 生成的花瓶只建了从瓶口看得到的那一段内壁**（vase_a 2220 面 / vase_b 3071 面、
  半径 0.05~0.14、全长在瓶颈里），腹部以内是空的 —— 这不是坏模型，
  `--extract-inner` 摘出来的正是这一段，够用。

### 分层探针的两个设计点（踩过才对的）

1. **「朝下」必须按 `--extract-region` 的 `cos=0.7` 拆成两档**：`朝下↓`（`ny ≤ −0.7`，
   真会被摘走的底面）/ `斜下`（−0.7 < `ny` < −0.6，斜着往下的**裙边**，本来就属于侧壁）。
   不拆的话，`vase_side` 底层「朝下 3018 面」看着像可贴区脏了，拆开一量**真底面只剩 71 面**。
2. **索引 accessor 必须按整数读**（`readUIntLE`）；用 `readFloatLE` 会把索引读成一堆浮点垃圾，
   症状是「所有三角形都落在同一层、内向面 0 个」—— 写临时脚本时踩到了。

落成正式脚本 `scripts/probe-layers.mjs` + `npm run models:layers`（只读）。和 `models:section`
互补：**截面探针答「横截面是圆是方」，分层探针答「纵向上哪一段是什么」**。

`VASE_REGIONS` 从「body / neck 两块可贴」改成**单块 `vase_side`**（用户只要「侧面外壁」，
没要求分瓶身瓶颈；注释里写了想分的话再加一条 `--extract-region` 按高度切）。

## 补记：闭环「`vase_side` 顶层 1259 个朝下↓面」

上一轮核对探针数据时发现 `vase_side` 里还留着一批 `ny ≤ −0.7` 的「朝下↓」面
（就是 `--extract-region` 会摘走的那一类），当时说要在注释里记下、结果漏了。这轮补上。

**先给探针加了「逐层半径」**（原来只报一个总中位半径，底层该摘的和顶层不该摘的混在一起算，
中位数被层数多的一方拉走 → 必然误判）。现在每个零件后面会打印：

```
↳ 朝下↓ 共   1330 面，半径 0.149~0.334（总中位 0.176）
   第  0 层     41 面 半径中位 0.254（同层 外壁 0.244 / 内壁  - ）
   第  1 层     30 面 半径中位 0.332（同层 外壁 0.375 / 内壁  - ）
   第 11 层   1259 面 半径中位 0.174（同层 外壁 0.198 / 内壁 0.122）
```

**结论：不是 bug，留着是对的。** 两个花瓶完全同构：

| 位置 | 面数 | 半径中位 | 同层外壁 | 同层内壁 | 判定 |
| --- | --- | --- | --- | --- | --- |
| `vase_a` 第 11 层（瓶口） | 1259 | 0.174 | 0.198 | 0.122 | 夹在内壁与外壁之间 → **外扩口沿的下表面** |
| `vase_b` 第 11 层（瓶口） | 414 | 0.113 | 0.096 | 0.088 | **比外壁还大** → 同上 |
| `vase_a` 第 0~1 层（底部） | 41 | 0.254 | 0.244 | — | ≈ 外壁 → 壁底交界的倒角 |
| `vase_b` 第 0 层（底部） | 37 | 0.156 | 0.150 | — | 同上 |

口径：**半径比同层 `_inner` 小才是内壁翻边（该摘）；≈ 或大于同层外壁就是外壁的一部分（留着）。**
口沿下表面从侧下方看得见，误摘反而在瓶口留一圈白边 —— 和「筒口翻边故意留在 `holder_side` 里」同源。

## 把 `fan_b.glb`（团扇）接入网站：只贴白绢 + 木框竹柄一个字节都不动

用户诉求：把 `文创商品模型/fan_b.glb` 放进来，**只对截图里那块白色区域贴图**，
白色要有**布料质感**，贴完**从扇子背面能看到正面图案的反向透影**，
**除白布以外**（雕花边框 + 竹柄）**保留原来的木质材质与原本的贴图效果**。

### 新发现：第 4 类模型 —— 自带烘焙贴图的扫描件 / AI 上色件

和前面所有商品都不同，`fan_b.glb` 有四个特征：**单个 mesh（50000 面）/ 单个连通块、
零硬边 / 已经带 UV（图集坐标）/ 带一张 4096² 三通道贴图集**（baseColor + normal +
metalRoughness，共 32.9 MB）。**几何上完全没有抓手** —— 连通性、硬边、朝向三套判据全失效。

于是换一条路：**采每个三角形 UV 重心处的贴图颜色**来分类。新增 `--extract-by-color`
+ 三个配套开关（`--uv-force` 强制重做平面 UV、`--material <零件>=keep|clean`、`--texture-size`
整数倍盒式降采样）。

```bash
npm run models:fix -- "../文创商品模型/fan_b.glb" --out public/models/products/fan_b.glb \
  --extract-by-color "node_0=fan_face;min=150;tol=16" \
  --uv-force "fan_face" --material "fan_body=keep" --material "fan_face=clean" \
  --texture-size 1024 --rename "node_0=fan_body"
# → fan_face 9097 面（可贴）/ fan_body 40903 面（保留）；35.17 MB → 3266.5 KB
```

### ★ 最大的坑：判据必须是「中性浅色」，不是「纯白」，而且**不能只看两个阈值点**

- 只给 `min>200` → 7353 面，**只圈到白绢的外表面**，内层漏掉 → **背面是一块白板**；
- `min=205` → 1115 面（当初只采 200 与 210 两点，断言「平台在 200~210」，整个白绢背面丢光）；
- **逐点扫 196→216** 才发现是**连续衰减、根本没有平台**；
- 真正稳定的是 **120~180 恒定 9097 面**；改用 `min=150;tol=16`（每通道 > 150 **且**通道差 ≤ 16）
  → 9097 面 = **两个完整圆盘**。木头是暖色（通道差 ≥ 40）自然被 `tol` 挡住。

**为什么内层这么要命**：这块绢面是**两层薄片、共用同一份 UV**。两层都圈进来，
`--uv-force` 的平面展开同时作用在两面 → **「背面看到正面反向透影」根本不需要做半透明**，
它就是这个结构的自然结果。

### ★ 另外三个真 bug（都是这轮暴露并修掉的）

1. **`sheenColor` 默认纯黑 → 帆布档的绒光一直是空的**。three r177 实测
   `new MeshPhysicalMaterial().sheenColor.getHexString() === '000000'`，**着色器拿它当绒光系数**
   → 只设 `sheen: 1` 在**渲染和导出两头都是零效果**。修法：`FinishSpec` 加显式 `sheenColor`，
   `applyFinish` 里 `sheen > 0` 时一定写；导出体检补断言 `sheenColorFactor[0] > 0`。
2. **保留零件的颜色被 8 位 hex 往返污染**（导出 `baseColorFactor` 从 `[0.8,0.8,0.8,1]`
   变成 `[0.7991,…]`）。第一次只加了浮点**回读**仍失败 —— 因为**首次读取**走的是 `m.color.getHex()`。
   修法：新增 `CLEAN_COLOR_RGB_KEY` 存线性浮点，首读用 `m.color.clone()`。修后**完全相等**。
3. **`verify-models` 报 `fan_b.glb 损坏 —— self is not defined`**：不是模型坏了，
   是 `GLTFLoader` 是浏览器用的（内部 `const URL = self.URL`），Node 没有 `self`。
   修法：自检前用 `geometryOnlyGlb()` 把 `images`/`textures`/`samplers` 与所有 `*Texture` 键剥掉。

### 页面侧：两个新 preset 字段

- `keepOriginalParts?: string[]` —— 这些部位**不套 finish / 不套调色板 / 连材质实例都不换**
  （先克隆一份材质，避免悬停写色串到别的部位）；
- `partFinishes?: Record<string, FinishId>` —— 按部位 id 覆盖 finish（`face: 'silk'`）。
- `fan_b` **故意不写顶层 `finish`** → 面板上不出现「表面质感」选择器。

### 新增「绢丝」质感档

`finish.ts` 加第 6 档 `silk`：`roughness 0.62` + `sheen 1 / sheenRoughness 0.3` +
更细密的织纹（`repeat 22`，帆布是 8）。**织纹贴图改为按 `repeat` 分开缓存**
