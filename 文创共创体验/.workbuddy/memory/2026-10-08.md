### 命令（比文档里的标准折扇命令多两条）

```bash
npm run models:fix -- ".../文创商品模型/fan_a.glb" --out public/models/products/fan_a.glb \
  --extract-region "node_0=fan_face_front;axis=+z;cos=0.5;y=0.201~1" \
  --extract-region "node_0=fan_face_back;axis=-z;cos=0.5;y=0.201~1" \
  --uv-force "fan_face_front,fan_face_back" \
  --material "fan_face_front=clean" --material "fan_face_back=clean" \
  --material "fan_ribs=wood" --rename "node_0=fan_ribs"
```

- `--uv-force`：自带 UV 是**图集布局**，留着会让用户上传的图案只采到一角 → 换成平面展开
- `--material …=clean`：自带烘焙贴图会**染在**用户图案上，且法线图是按旧 UV 烘的 → 清成白坯
  ⚠️ **默认档是 `{...source}` 浅拷贝、会把贴图一起继承**，「不写 `--material`」≠「干净」
- 产物 **1571.0 KB**（旧 1350.6 KB），md5 `6ac9ac9c82873f7f6be9dab15d776f2c`
- 顶点数变多（10775 / 11088 / 18021 vs 9378 / 8903 / 14549）：自带 UV 的接缝在补 UV 时又被拆了点。
  **面数、包围盒不变就说明拆分正确**，顶点数变化不影响识别。

### 修掉 `scripts/fix-model.mjs` 的孤儿贴图问题（顺带，影响所有模型）

第一次生成出来 **27027 KB** —— 材质里一张贴图都没有，但 `images=3 textures=3` 还在。
根因：脚本对 `images / textures / samplers` 是 **1:1 全量搬运**。

修法：把搬运**移到材质全部生成之后**，扫描 `outMaterials` 里所有 `xxxTexture.index`，
只搬被引用的那些，重映射 `images / textures / samplers` 下标，最后统一改写材质里的 `index`。
- ⚠️ 重映射要用**记下来的 oldIndex**（`{...source}` 浅拷贝 → 多个零件**共享同一个贴图对象**）
- ⚠️ **不能提前按零件名预判**：`instance.name` 是**源名 `node_0`**，而 `--material` 的键是拆分后的
  输出名（`fan_face_front` / `fan_ribs`），那是在 `instances.forEach` 里才产生的

**回归验证（关键）**：用团扇 `fan_b`（走 `keep` 路径）重跑到 `_tmp`，与现有文件对比 ——
3344924 vs 3344928 字节（差 4 字节）；语义级对比（nodes / meshes / materials / textures / images 的 md5、
**bufferView 字节 md5 集合**）**全部一致** → 只是 bufferView 排列顺序变了（贴图视图从几何之前挪到之后）。

### 手法：**先断言再删**（这次最大的经验）

用一次性 py 脚本按行删，每一步先 `assert` 目标行**内容含关键词**再 `del`，
任一步不符就**中止且不写回**（失败时文件保持原样，不会留下改坏的半成品）。三个坑：

1. `Edit` 工具做**长段 / 含反引号与全角标点**的匹配**反复失败** → 直接改 py 按行操作最稳。
2. 删「对象 / 条目」时**不能只认 `},`** —— `e2e-paint.mjs` 的 steps 数组里，元素结束行也是 `      },`，
   `strip()` 之后和段落结束的 `  },` 一模一样。**必须连缩进一起比**（`s == '  },\n'`）。
3. **跨行匹配**：根 README 的商品列表一行放不下，`\`fan_a\`（折扇）、` 落在**下一行** ——
   拿第一行当 needle 去找那个子串必然落空。改成**行内 `replace`**（needle 就取那个子串本身），
   并且所有文字改动都别再"整行覆盖"，避免把同一行后半段吃掉。
