## 正式模型 mug_a.glb 进场（混元 3D + 3ds Max 拆分）

用户把在 Max 里拆好的 `mug_a.glb` 放到 `网页/文创商品模型/`，只拆了两块：`cup_body` / `cup_handle`。
放进来后发现：**部位名天然精确匹配，`regions` 配置一行都没改** —— 印证了「按规范命名即零改动」。
但模型本身有两个毛病必须先修，于是写了 `scripts/fix-model.mjs`（`npm run models:fix`）。

### Max 导出的 GLB 常见的两个毛病（这次都踩到了）

1. **没有 `TEXCOORD_0`**。只有 NORMAL + POSITION。没有 UV 就完全贴不上图，
   网页端会提示「这个部位没有 UV 坐标」并跳过，`models:verify` 报「没有任何 mesh 带 UV」。
   原因大概是 Max 的 ATF 导出器（日志里是 `ATF::MaxATFProducer → ATF::GLTFConsumer`）
   在对象没有 UVW 通道时干脆不写 UV。
2. **材质是 `fallback Material`**：`baseColorFactor = [0,0,0,1]`，且
   **`metallicFactor` / `roughnessFactor` 缺省 = 1**（glTF 默认值）→ 渲染出来是一坨发暗的金属块。
   场景里哪个对象没给材质就会这样。实测截图 `11-新模型第一次.png` 通体发黑。

另外 Max 会给每个对象套一层「外层 ×1000 / 内层 ×0.001」的父子节点 + 一个平移，看着很唬人。

### `scripts/fix-model.mjs` 做了什么

- **补 UV**：按部位名选投影（`PROJECTION_BY_PART` 表：回转体 `cylinder-y`、片状 `planar-z`），
  表里没有的按包围盒形状猜。**接缝拆点**（跨 0/1 的三角形把 u 小的那几个顶点 +1 并复制一份），
  否则那块三角形会把整张贴图反向压缩成一条显眼的带子。
- **柱面投影必须绕这个部位自己的轴**（用 XZ 包围盒中心），不能绕场景原点 ——
  模型导出时整体平移过，绕原点转会让图案一侧压扁一侧拉长。这条是踩出来的。
- **UV 方向**：`u = (atan2(x - axisX, z - axisZ) + π) / 2π`（接缝在 -Z 背面、图案中心正对 +Z 相机），
  `v = 1 - (y - minY) / height`（glTF 里 `uv.v = 0` 是图片**顶部**，所以 v 要反过来）。
- **修材质**：颜色归白、金属度 0.05、粗糙度 0.65、doubleSided，**材质名改成部位名**（双保险）。
- **烘焙节点层级**：把世界矩阵写进顶点，输出扁平结构（`world = parent · child`，列主序 4×4）。
  已用体检页对比确认烘焙后几何与原始模型**完全一致**。
- **部位体检**：并查集按三角形连通性分组。**必须先按坐标焊接**（round 到 1e-4），
  否则混元那种「位置重合但不共享顶点」的同心环会把一整块面误报成几十块。
  焊接后 `cup_handle` 报出 2 块、`cup_body` 报 1 块，直接指出了下面的问题。

### 用户模型的问题：`cup_handle` 里混进了杯底

体检 + 分色渲染（`12-模型体检.png`）确认：
`cup_handle` = 把手（3694 点，0.281×0.560×0.149）+ **杯底**（4365 点，0.658×0.070×0.658）。
是拆模型时「选择面」多选/漏选了。

后果两条：① 点把手贴图，杯底也跟着变；② 补 UV 时包围盒被杯底撑大，
把手的 UV 只落在图像右侧约 30%（实测截图 `15-贴图验证-2把手.png` 里把手整块变成测试图右上角那个绿色方块）。
**已告知用户回 Max 重新分离，改完只需重跑 `npm run models:fix` + `models:verify`。**

## 第二轮：新 mug_a（已加 UV）进场 —— 消红警告 / 内壁不贴图 / 陶瓷质感

用户把「加过 UV 的 mug_a.glb」重新放进 `网页/文创商品模型/`，带着两个问题：
①画面正中还有**红色警告**，且**杯子内壁不要被贴图**（问能不能代码处理、要不要回 Max）；
②**陶瓷质感没体现出来**（问要改什么、要不要提供素材）。

### 问题①拆成三件事，全部用代码解决，用户不用回 Max

**(a) 红色警告根因**：drei 的 `<Environment preset="studio" />` 要去 CDN 拉
`studio_small_03_1k.hdr`，离线/弱网必失败，被 `SceneErrorBoundary` 兜成画面正中的红条。
→ 删掉 `<Environment>`，新建 `src/three/studioEnv.ts`：用
`new THREE.PMREMGenerator(gl).fromScene(buildStudioScene(), 0, 0.5, 120)` **现搭影棚现烘**，
零外部资源。`<Scene>` 里换成 Canvas 内的 `<StudioEnvironment>`（拿 `useThree` 的 gl/scene，
`scene.environment = 贴图`、`scene.environmentIntensity = intensity`，卸载时还原）。
烘失败返回 `null` 退化成纯灯光，绝不让整个场景崩。

**(b) 内壁不贴图**：新导出的模型里内壁与杯身是**连着的一整片**，Max 里刷选极易漏。
→ 给 `scripts/fix-model.mjs` 加 `--extract-inner "cup_body=cup_inner"`：按**几何法向**自动拆。
三角形叉积得几何法向，`radialDot = (n·r̂)`，`< -0.5` 的三角形半径**取中位数**当 `innerRadius`
（自估，不写死常数）；近水平面用 `ny > 0 && radius < innerRadius` 判内底；其余按 `radialDot < 0` 判内壁。
`regions.ts` 里 `cup_inner` 设 `paintable: false`（保留部位）。

**(c) 上轮遗留的杯底混进把手**：加 `--island-names "cup_handle=cup_bottom,cup_handle"`，
按**坐标焊接 + 并查集**做连通性分组，每块独立成件。这次杯底 8575 面（占 54.1%），
拆出来后把手的 UV 不再被挤到一角。

拆分实现要点（改 `fix-model.mjs` 时要保持）：
- 主循环从「一个输入零件 → 一个输出零件」重构成「一个输入零件 → **多个**输出零件」，
  抽出 `emitPart()` 复写 accessor / material / mesh / node 那整段。
- `buildSubPart()` 做顶点压缩重排：POSITION / NORMAL / UV 一起搬，索引重映射。
- 体检告警**直接输出可复制的修复参数**（`· 自动拆：加参数 --island-names "…"`），
  用户看到就能照着跑。

### 问题②陶瓷质感：两个原因叠加，且**不需要用户提供任何素材**

- **原因 1（材质层没做）**：白瓷 = 坯体（偏哑光）+ 釉层（锐利高光），是**两层反射**。
  `MeshStandardMaterial` 只有一层 → 必须升级成 `MeshPhysicalMaterial` 用 **clearcoat**。
- **原因 2（环境贴图没加载）**：就是上面的红警告，没有环境贴图就没有高光可反射，
  再好的 roughness 也是平的。

新增 `src/three/finish.ts`：5 档 `FinishId`（`glaze` 陶瓷釉面 / `matte` 哑光陶土 /
`satin` 半哑光 / `metal` / `fabric` 帆布），每档写 `metalness / roughness / clearcoat /
clearcoatRoughness / envMapIntensity / sheen / sheenRoughness`。
茶杯/花瓶默认 `glaze`（`roughness 0.34` + `clearcoat 1` / `clearcoatRoughness 0.05`）、
冰箱贴 `satin`、帆布包 `fabric`、扇子 `matte`。

### 三个踩出来的坑

1. **`ensurePhysicalMaterial()` 不能用 `MeshPhysicalMaterial.prototype.copy`** ——
   会把 clearcoat 系列写成 `undefined`。必须 `THREE.MeshStandardMaterial.prototype.copy.call(next, src)`，
   并把 `defines` 补成 `{ STANDARD: '', PHYSICAL: '' }`，否则 **PHYSICAL 着色器根本不编译**。
   换实例后原本 `onBeforeCompile` 挂的补丁没了，要清掉 `userData.__colorize` 标记。
2. **three 会覆盖 `material.envMapIntensity`**：当 `material.envMap === null &&
   scene.environment !== null` 时，渲染器每帧用 `scene.environmentIntensity` 覆盖它
   （`three.module.js:17230`）。想让「档位权重 × 环境反光滑块」真正生效，
   **必须把烘好的贴图挂到 `material.envMap` 上** —— 所以 `StudioEnvironment` 通过
   `onReady(map)` 把贴图从 Scene 作为 prop 下发到 `Configurator` → `BodyTintedConfigurator`
   （Canvas 内外只能靠 props 传，这条是老约定）。
3. **高光带出不来是灯太宽**：程序化影棚前 3 版都偏「平光灰」。最终把
   **天空梯度压暗**（`0.09 / 0.018 / 0.003`）+ **面板灯收窄提亮**（左前竖条灯宽 0.5、强度 11），
   白瓷杯身上才出现清晰的**细长竖条高光带**。灯越窄，高光越锐利。
   标定后的 `DEFAULT_LIGHTS`：`exposure 0.85 / environment 1 / key 0.4 / fill 0.18 / ambient 0.04`。

### 新增脚本与校验

- `scripts/check-material.mjs`：读回每个零件的真实材质（type / metalness / roughness /
  clearcoat / sheen / envMapIntensity / hasEnvMap）。实测 `MeshPhysicalMaterial`、
  `clearcoat=1`、`roughness=0.34`、`envMapIntensity=0.85`。
- `scripts/check-export.mjs`：`Browser.setDownloadBehavior` 下载 GLB → 解析核对。
  实测 `extensionsUsed: ["KHR_materials_clearcoat"]`、**只有 `cup_body` 带
  `baseColorTexture`**、底色干净、无 emissive。⚠️ 导出器对**纯白会省略**
  `baseColorFactor`（得到 `undefined`），断言要写 `v === undefined || v.every(n => n === 1)`。
- `scripts/e2e-finish.mjs`：依次点 5 档质感截对照图。截图前要 `hidePanels()`
  把 `.model-selector/.color-controls/.studio-dock/.toolbar` 设 `visibility: hidden`，
  裁切区域 `{x:250, y:80, w:820, h:760}`。
- `scripts/e2e-paint.mjs` 重写为 **15 项断言**，读回 `window.__scene`（`import.meta.env.DEV` 门控）

  ⚠️ `RegionPicker` 未上传图片时不渲染，chips 断言要放在贴图**之后**。
