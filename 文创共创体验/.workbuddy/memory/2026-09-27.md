## 文创商品 AI 定制器（网页端）从零搭起来

按要求读了 `网页/AI执行任务.md`，产出项目 `网页/wenchuang-customizer/`。

### 关键决策与踩的坑

- **`git clone` 拉不到底座**：`gorhorvat/product-configurator-3d` 仓库 72MB，本机到 GitHub 的实测速度只有 ~25KB/s，
  `git clone` 两次都在传 15MB 左右断流（`RPC failed; curl 56 schannel`），codeload tarball 45 秒只下到 1.1MB。
  **改用 GitHub raw + contents API 逐个拉源码**，自己组装出项目目录（缺的只是底座自带的 3 个示例模型 + PS5 控制器）。
- 因此把底座自带的 4 条示例配置拆成 `LEGACY_PRESETS` 常量，不放进默认的 `MODEL_PRESETS`，
  避免下拉框里出现点了就 404 的选项。想恢复只需改成 `[...LEGACY_PRESETS, ...WENCHUANG_PRESETS]`。
- **没有正式 GLB 就没法联调** → 写了 `scripts/make-placeholder-models.mjs`，用纯代码生成 10 个带正确 UV 的占位 GLB
  （回转体/长方体/扇面三类几何），正式模型到位后同名覆盖即可。
- **R3F 的 `<Canvas>` 内部不保证能读到外部 React Context** → 贴图链路需要的回调（commitPaint / registerThree /
  registerHighlighter / status）全部从 Scene 用 **props** 显式传进 Canvas，不依赖 context 穿透。
  这一点是架构上最容易埋雷的地方，下次做 R3F 也照这个来。
- 贴图机制按要求用「Raycaster 点击选面」，不靠材质名。共用材质先 `material.clone()`。
  克隆会丢掉 `applyColorize` 的 `onBeforeCompile` 补丁但保留 `userData.__colorize` 标记，
  必须先清标记再重新 `applyColorize`，否则全彩模式会静默失效（已在 `surfacePainter.ts` 里处理）。
- 在 Canvas 里加了 `SceneErrorBoundary`：离线时 drei 的 `<Environment preset>` 拉不到 HDRI 会抛错，
  没有隔离会整屏白；模型 404 同理。
- 相机从 `[0,0.2,2]` 挪到 `[0,0.35,2.6]`、`maxDistance` 6→8，商品（归一化到 1.2 单位）取景更舒服。

### 第二轮补充验证：滑块微调到底有没有作用到贴图

上一轮只确认了「滑块出现」，没确认「滑块生效」——CDP 用鼠标点 `<input type=range>` 改不动值。
这一轮**改用原生 value setter + `input`/`change` 事件**设值，读数成功变为 `["0.00","0.00","1.00","3.00","45°"]`。

关键手法是给 WebGL canvas 做**像素签名**：缩到 64×36 求加权像素和，前后对比。
先关自动旋转、连取两次签名得到静止噪声基线（0.005%），改参数后签名变化 **1.59%**，
是噪声的 ~320 倍 → 画面变化确实来自贴图参数而不是相机漂移。截图 `04-微调后.png` 里格纹 visibly 变斜、变密，
人眼和像素两条证据闭环。这个「像素签名 + 噪声基线」的判读方法已写进 skill `edge-cdp-headless-e2e`。

收尾全量校验：`models:verify` 10/10、`tsc -b` exit 0、`eslint .` 0 error（2 warning 来自底座原有代码）。

### 新增一键启动 `npm run dev:all`

用户问「项目网页链接是什么 / 怎么运行」，而原来必须开两个终端（`npm run server` + `npm run dev`）才跑得起来，
摩擦有点大。加了 `scripts/dev-all.mjs`（**零依赖**，不引 concurrently）：

- 用 `process.execPath` 直接跑 `server/index.js` 和 `node_modules/vite/bin/vite.js`，
  绕开 Windows 上 `spawn('npm.cmd')` 必须 `shell: true` 的坑；
- 给两个子进程的 stdout/stderr 加 `[后端]` / `[前端]` 彩色前缀，日志不会混在一起；
- 任一子进程退出就一起收掉另一个，避免「后端死了前端还在跑、点生图报 502 查不出原因」。

实测：一条命令起 3001 + 5173，且 `http://localhost:5173/api/health` 走代理返回 200（代理通 = canvas 不会被跨域污染）。
首页截图存 `docs/联调截图/00-首页.png`，确认 10 个配置 / 4 块面板 / WebGL2 都在。

**本机访问地址：`http://localhost:5173/`**（前端），后端 `http://localhost:3001`。
注意 vite 只监听 `[::1]:5173`（IPv6），`http://127.0.0.1:5173/` 不一定通，用 `localhost` 最稳。

### 修复「模型太亮 / 过曝」并加上可调的灯光面板

用户反馈商品发白过曝。**诊断结论：不是材质问题，是光照叠加。**

- 先排除了金属度嫌疑：文创商品 `colorMode: 'body'` → `BodyTintedConfigurator`，
  它只写 `material.color` / `envMapIntensity`，**不动 metalness/roughness**，
  所以用的是占位 GLB 自带的 `metallicFactor 0.05 / roughnessFactor 0.65`（正常介电质）。
  底座 `PerMaterialConfigurator` 里那套 `metalness=0.5/roughness=0.2` 是给 PS5 手柄的，我们不走。
- 真凶：`<Environment preset="studio">` 当 IBL + 两盏平行光（1.0 / 0.5）+ 环境光 0.3，
  再叠 R3F 默认的 `ACESFilmicToneMapping` + 曝光 1.0。这套是底座为深色手柄调的。
- **量化**（写了 `exposure-probe.mjs`，用「与背景色差」切出商品像素再统计亮度分布）：
  「花瓶·细颈」平均亮度 **234.1/255**、**46.2%** 像素 >240（丢细节）、**18.6%** >250（死白）。
- 修复：新建 `src/three/lighting.ts`（`DEFAULT_LIGHTS` = 曝光 0.85 / 环境 0.35 / 主光 0.70 / 补光 0.30 / 环境光 0.15），
  `Scene.tsx` 里 `LightRig` 组件负责把曝光写进 `gl.toneMappingExposure`（它不在 props 体系里，得用 `useThree` 拿 renderer）。
  结果：平均 **196.3**、>240 降到 **8.7%**、>250 归 **0%**，最大 247（高光保留渐变）。
  截图 `06-灯光过曝（调整前）.png` / `07-灯光修复后.png` 对比明显：调整前瓶身是无体积感的纯白块。
- 加了工具栏 ☀ **「灯光与曝光」弹出面板**（`LightingPanel.tsx`，5 档滑块 + 恢复默认），
  面板测试 5 档全部数值生效，「恢复默认」能精确复原。
- `useThree` 要从 `@react-three/fiber` 导入，**drei 不导出它**（踩了一次 tsc 报错）。
- drei `<Environment>` 的 `environmentIntensity` 确认有效：无头实测 env 0.35→1.20 时平均亮度 195.8→233.0。
  注意它走的是 `EnvironmentCube`（preset 分支），该组件 effect 没有依赖数组，所以改 prop 每次都会应用。

**顺带踩的坑（已写进 skill `edge-cdp-headless-e2e`）**：无头 Edge 截图会给**中文段落**叠一层蓝/粉色高亮框，
看着极像 `::selection` 或父级背景，很容易误判成自己的 CSS 写错了。自证方法：
同容器内放中英文两段同 class 文本 → 只有中文段被标记；把容器背景改完全不透明后色块仍在；
`getSelection()` 为空、`elementsFromPoint` 最上层就是自己。真实浏览器不会出现，交付截图时把长中文段落
挪进 `title` 或精简成短文案即可规避。

### 第三轮：用户要在 3ds Max 里拆部位 —— 加了「部位命名表」机制

用户反馈「你的功能没有对每个面做分割，我正在 3Dmax 里分割并命名，是不是导出 glb 放进文件夹就行」。
核心工作是把「贴图落在哪」从「点中哪个 mesh」升级成「点中哪个**部位**」。

**新增 / 改动**

- `src/three/regions.ts`（新）：`RegionConfig` 类型 + 名字匹配 + 场景扫描。
  关键认知：**glTF 里只有「对象名」和「材质名」能活下来**，命名选择集 / 平滑组 / 图层全部不导出；
  且 3ds Max 的 glTF 导出器**会把层级拍平**，所以不能靠父对象分组。
  匹配三级优先级：完全一致 → 去 GLTFLoader 补的 `_1/_2` 后缀 → 分词包含；按区域取「全场最高置信度」避免误吞。
  **该文件必须保持零相对依赖**，否则 Node 直读 TS 时解析不了不带扩展名的 `./surfacePainter`。
- `surfacePainter.ts`：`ensureOwnMaterial` → `preparePaintTargets`（支持一次写多个零件；
  只在材质还被「本次范围之外」的网格共用时才 clone，同一原材质只克隆一次，多零件共用一份克隆体）。
- `textureStudio.tsx`：`commitPaint` 支持区域扩展；新增 `paintRegion(regionId)`；
  命中保留部位时明确拒绝；命中未登记零件时退化成「只贴所选表面」并提示；
  `liveStackRef` 改成栈，`clearTexture` 后进先出逐次回滚（原来只能移除最后一次，会残留）。
- `RegionPicker.tsx`（新）：**「可贴图部位」按钮条** + 命名自检；名字对不上时把模型里的**真实零件名**列出来。
- `scripts/make-placeholder-models.mjs`：占位模型也按同一套名字拆开（`revolveRange` 切剖面、
  `boxFaces` 选面、`torusArc` 做杯把），一个部位 = 一个 node + mesh + material 且三者同名。
- `scripts/verify-models.mjs`：改成**直接 import modelPresets.ts**（Node 22.18+ 自带类型擦除，
  不需要编译，也不用正则解析），跑的就是前端同一份匹配逻辑，打印「零件名 ↔ 中文部位」对照表。
- `docs/模型拆分与命名规范.md`（新）：给用户照着操作的全套规范（两种拆分方式、导出设置、
  Max glTF 导出器的已知限制、UV 要求、检查清单、要提供什么信息）。

**验证**（`e2e-region.mjs`，13/13 通过）：点 3D 模型上的把手 → 被「保留部位」拦住且什么都没贴上；
