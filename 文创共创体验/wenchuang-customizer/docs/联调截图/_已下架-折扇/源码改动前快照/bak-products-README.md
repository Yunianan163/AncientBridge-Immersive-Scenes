  当前零件：`cup_body` / `cup_inner` / `cup_handle` / `cup_bottom`，四个部位全部**精确匹配**。
- **`bag_a.glb` 也是正式模型**（混元 3D 直接出的**一整块软体**，没有硬边、没有分块，
  用 `npm run models:fix --extract-region` 按「朝向 + 包围盒范围」把**正反两面各圈一块**）。
  当前零件：`bag_front` / `bag_back`（都可贴）/ `bag_body`（侧边与提手，保留），三个部位全部**精确匹配**。
- **`bag_b.glb` 也是正式模型**（同样是 AI 出的一整块软体，50004 面 / 单个连通块 / 一处硬边都没有 / 无 UV）。
  和 `bag_a` 的区别是**可贴区不是整块面板，而是面板正中那块矩形** —— 按设计稿上画的红框量出来的
  （`x=0.12~0.915` / `y=0.10~0.42`，正反两面同一组）。同样三个零件、全部**精确匹配**。
- **`holder_a.glb`（圆）/ `holder_b.glb`（方）也都是正式模型**（AI 出的一整块软体：各 50000 面 /
  单个连通块 / 无 UV）。这两只**不是圈矩形**，而是用 `--extract-inner` 按法向**把整个筒腔摘掉**，
  再按朝向摘掉筒底，只剩筒身外壁可贴（用户要求「只对侧面外壁贴图」）。
  **两条命令一模一样** —— 判据写的是「法向 / 朝向」，与截面形状无关：
  `holder_a` 是正圆（截面半径恒定 0.338），`holder_b` 是带圆角的方形（半径 0.319↔0.420、每 90° 循环）。
  当前零件两边完全一样：`holder_side`（筒身外壁，可贴）/ `holder_inner`（筒口与内壁，保留）/
  `holder_bottom`（筒底，保留），六个部位全部**精确匹配**，所以**共用同一张 `HOLDER_REGIONS` 表**。
  实测面数：圆 `21394 / 3070 / 26646`，方 `21639 / 4419 / 24658`。
- **`vase_a.glb`（圆肚）/ `vase_b.glb`（细颈）也都是正式模型**（AI 出的一整块软体：各约 50000 面 /
  单个连通块 / 无 UV），拆法和两个笔筒**完全一样** —— `--extract-inner` 摘内腔、`--extract-region`
  摘朝下的底，剩下就是瓶身外壁（用户的要求同样只有一句：「只对侧面外壁贴图」）。
  当前零件：`vase_side`（瓶身外壁，可贴）/ `vase_inner`（瓶口与内壁，保留）/ `vase_bottom`（瓶底，保留），
  两边零件名一致、**共用同一张 `VASE_REGIONS` 表**。
  实测面数：圆肚 `2220 / 4644 / 43902`，细颈 `3071 / 2987 / 44782`。
  ⚠️ 但**底部那一步的 `y` 区间不能照抄笔筒的 `0~0.06`**：花瓶的底是**两级**的（外圈一圈朝下的环 +
  中心一块最低的底盘，几何上互不相连），`0.06` 正好切在它中间，会把半个凹底留在可贴区里
  （症状：点外壁贴图，瓶底看不见的凹面也跟着被贴上）。要放到 `0~0.12`。
  ⚠️ 另外 **AI 生成的花瓶只建了从瓶口看得到的那一小段内壁**（2000~3000 面，全长在瓶颈里），
  腹部以内是空的 —— 这不是模型坏了，`--extract-inner` 摘出来的就是这一段，够用。
- **`fan_b.glb`（团扇）也是正式模型**，而且是**第 4 类模型**：和上面所有模型都不同，它**不是白模** ——
  原始文件是一个 **单 mesh（50000 面）、单个连通块、零硬边，但自带一张 4096² 的烘焙贴图集**
  （baseColor + normal + metalRoughness 三张，共 32.9 MB）。几何上完全没有抓手，
  所以分区**只能按贴图颜色认**（`--extract-by-color`）。
  当前零件：`fan_face`（白色绢面，可贴）/ `fan_body`（雕花边框 + 竹柄，保留），两个部位全部**精确匹配**。
  ⚠️ **`fan_body` 是「一个字节都不许动」的**：贴图、法线图、金属粗糙度全部原样保留
  （模型侧 `--material fan_body=keep` + 页面侧 `keepOriginalParts: ['body']`），
  导出时脚本会拿它和源文件**逐字段比对**。详细做法见下面「第四类：自带烘焙贴图的扫描件」。
- **`mug_b.glb`（直筒款茶杯）也是正式模型**（AI 出的整块软体：50000 面 / 单个连通块 / 零 UV / 正圆截面）。
  它既不是「圈一块」也不是「摘内腔」，而是**按高度切两刀** —— 因为它**没有把手**，
  可贴区就是杯身那一圈外壁（用户给的红框是「唇边下沿 → 底部」）：

  ```bash
  npm run models:fix -- "../文创商品模型/mug_b.glb" --out public/models/products/mug_b.glb \
    --extract-region "node_0=cup_inner;axis=+y;cos=-1;y=0.85~1" \
    --extract-region "node_0=cup_bottom;axis=-y;cos=0.7;y=0~0.08" \
    --rename "node_0=cup_body"
  ```

  第 ① 刀的 `axis=+y;cos=-1` 是**故意的**：`cos >= -1` 恒成立，朝向条件失效，
  **退化成纯高度切割**，一刀拿走整段「唇边 + 杯口内壁」（25807 面 → `cup_inner`，保留），
  切点正好落在唇边下沿（实测 y=0.904）；第 ② 刀再从剩下的里摘朝下的底
  （3628 面 → `cup_bottom`，保留，它会报「2 块互不相连」—— 那是两级底的**真实几何**）。
  剩下 23097 面 = `cup_body`。
  ⚠️ 第 ② 刀的 `y=0.08` 是**相对第 ① 刀切完之后的包围盒**算的（多刀会连锁），改了第 ① 刀就得重算第 ② 刀。
  ⚠️ **它没有把手**，所以 `CUP_REGIONS` 里的 `handle` 标了 `optional` ——
  两个茶杯仍然**共用同一张表**。材质是**塑料不是陶瓷**，preset 里 `finish: 'plastic'`。
- 只剩 `fan_a` 还是 `scripts/make-placeholder-models.mjs` 生成的占位近似体，
  造型不代表最终外观，但**部位已按同一套规范拆好并命名**，可以直接用来联调整条链路。
- `magnet_a.glb` / `magnet_b.glb`（冰箱贴·方 / 圆）**文件还在，但两个都已经不在下拉框里** ——
  这两个位置先后让位给笔筒了。想恢复的话把配置加回去即可，模型文件不用重新做
  （`src/data/modelPresets.ts` 里注释保留了 `MAGNET_REGIONS` 的定义，放开即可）。

> 材质是 `fallback Material`**，原样放进去是渲染不出来、也贴不上图的。

### 为什么需要 `models:fix`

Max 导出的 GLB 经常带着几个毛病，直接放进项目是**用不了**的：

| 毛病 | 后果 | `models:fix` 怎么处理 |
| --- | --- | --- |
| 没有 UV（`TEXCOORD_0`） | 贴图**完全贴不上去**，点上去提示「没有 UV 坐标」 | 按部位形状自动补（回转体走柱面、片状走平面），接缝拆点不留拉伸条带 |
| 材质是 `fallback Material`（对象没给材质） | `baseColorFactor` 纯黑 + 金属度/粗糙度缺省 = 1，渲染出来**一坨发暗的金属块** | 颜色归白、金属度 0.05、粗糙度 0.65 |
| 外层 ×1000 / 内层 ×0.001 的父子节点 | 不影响使用，但给后续处理添乱 | 烘焙进顶点，输出扁平结构 |

它还会做一次**部位体检**：如果一个部位里有好几块互不相连的面，会明确报出来
（典型是拆分时多选/漏选了面，比如杯底被分进了把手）—— 这种问题肉眼在网页上很难发现。
体检发现问题时，**输出里会直接给出可以复制的修复命令**，照着跑即可。

### 四个自动拆分开关（不用回 3ds Max）

有四种「在 Max 里选面特别难」的情况，代码能自动拆：

| 参数 | 拆什么 | 原理 |
| --- | --- | --- |
| `--island-names "<源零件>=<名1>,<名2>,..."` | 一个零件里**互不相连的碎块**拆成多个零件 | 按坐标焊接顶点做连通性分组（并查集），每块独立成件；块数要和给的名字数一致 |
| `--extract-inner "<源零件>=<内壁名>"` | 从杯身/瓶身里**按几何法向拆出内壁与内底** | 三角形叉积算几何法向，`(法向·径向) < 0` 判为朝里的面；近水平面再用「法向朝上且半径小于内壁半径」判内底 |
| `--extract-region "<源零件>=<新名字>;axis=+z;cos=0.7;y=0~0.53"` | 从**一整块光滑软体**上圈出一块（按「朝向 + 包围盒归一化范围」） | 四个轴对齐半空间把面**真正切开**（不是整块丢三角形），切出来的边界是一条直线。<br>★ **要「整圈外壁」就把 `cos` 设成 `-1`** —— 朝向判定失效，退化成**一把纯高度切刀**（直筒款茶杯 `mug_b` 就是一刀切走「唇边 + 杯口」整段）。⚠️ **多刀会连锁**，后一刀的 `y` 按「当前那块」的包围盒算，改了前一刀要重算 |
| `--extract-by-color "<源零件>=<新名字>;min=150;tol=16"` | 从**自带烘焙贴图的扫描件 / AI 上色件**上按**贴图颜色**认出一块 | 采三角形 UV 重心处的贴图颜色，判「中性浅色」（见下面「第四类」） |

```bash
# 例：杯底被误并进了把手 → 从 cup_handle 里拆出 cup_bottom
#     杯口内壁和外壁连成一整片 → 从 cup_body 里按法向拆出 cup_inner
npm run models:fix -- "文创商品模型/mug_a.glb" --out public/models/products/mug_a.glb \
  --island-names "cup_handle=cup_bottom,cup_handle" \
  --extract-inner "cup_body=cup_inner"
```

#### `--extract-region` 怎么用（AI 建模出的「一整块软体」专用）

**适用场景**：混元 3D 这类 AI 直接生成的一整块模型 —— 整个包体是**一个连通块**、
相邻面二面角全都 < 25°（**没有任何硬边**），所以 `--island-names`（靠连通性）和
`--extract-inner`（靠轴向法向）**都用不上**。

参数写成 `<源零件>=<新名字>;键=值;键=值`：

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `axis` | 主朝向：`+x` / `-x` / `+y` / `-y` / `+z` / `-z` | `+z` |
| `cos` | 法向与 `axis` 的夹角余弦**下限**（越大越只留「正对着」的面） | `0.7` |
| `x` / `y` / `z` | 该轴的**归一化区间**（`0`=该轴最小端、`1`=最大端），形如 `0.5~1`；省略即不切 | 不切 |
| `r` | 到 `center` 的**平面距离**的归一化区间（`1` = 该区域顶点里最远的那个）。给**扇环 / 环带**这类轴对齐包围盒圈不出来的区域用。⚠️ 这一条是**按三角形重心整块归类、不做几何裁切**（半径边界在真实模型里通常正好是网格自己的边界），和 `x/y/z` 的「用平面真切开」不一样 | 不切 |
| `center` | `r` 的圆心，写**世界坐标**（`1.6583,0.1069`）。⚠️ 不是模型里的局部坐标 —— `--extract-region` 拿到的顶点已经被父节点的变换乘过了 | 包围盒中心 |

> `r` / `center` 是 2026-10 拆折扇时补上的通用能力，目前**没有正式模型在用**：
> 一度以为折扇扇面得靠半径圈，实测**不需要** —— 扇面内弧本来就是网格自己的边界，
> 靠「朝向 + 高度」两刀就分干净了（见下面折扇那一节）。真要用先拿 `--dry` 核对面数、
> 再出目视分类图交叉验证。

`--rename "<旧名>=<新名>"` 用来给**剩下那一块**改名（拆完源零件名还留着，指的就是补集）：

```bash
# 帆布包 bag_a：AI 出的整块软体，把「正面」和「背面」各圈成一块可贴图区
npm run models:fix -- "文创商品模型/bag_a.glb" --out public/models/products/bag_a.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.7;y=0~0.53;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.7;y=0~0.53;z=0~0.5" \
  --rename "node_0=bag_body"
# → bag_front 5822 面 / bag_back 4548 面（都可贴） / bag_body 47016 面（侧边与提手，保留）
```

**`--extract-region` 可以串联用**（给同一块料连圈几处）：**第二条规则以第一条剩下的几何为输入**，
所以「先圈正面、再从剩下的里圈背面」在同一次运行里就能做完，中间不用落盘。
⚠️ 注意区间是**相对当次输入几何自己的包围盒**归一化的 —— 串联时第二次的
`x/y/z` 指的是「剩下那块」的包围盒。这里能直接用 `z=0~0.5`，是因为 `bag_body` 的 z 范围
几乎和原始模型一样（补集里含了正面的内表面，把包围盒撑回了原来的大小）。

**背面为什么用 `planar-z-back`**：观察点在 -Z 时 X 轴在屏幕上左右相反，
同一套 `planar-z` 贴上去，文字和印章会**左右镜像**。所以投影表里给 `bag_back`
配了 `planar-z-back`（只把 `u` 翻转，`v` 不动 —— 上下与站在前面还是后面无关）。
这类「从背面看」的部位都该用它。

参数怎么估出来的：先跑 `--dry` 看体检报告，再用 `model-inspect.html` 分色确认。
`y=0~0.53` 的上界是**袋口折边**的分界高度（超过它面积占比骤降，因为那是提手）；
`z=0.5~1` / `z=0~0.5` 是**沿深度从中间切一刀** —— 模型是闭合壳体，
正面外壁在 z 后半、法向朝 `+z`，背面外壁在 z 前半、法向朝 `-z`，
两面各自的内表面朝向正好相反，会被 `cos` 和 `z` 区间同时挡掉。

#### 要让可贴区**严格贴合设计稿上画的框**（`bag_b` 的做法）

`bag_b` 是「只让面板正中那块矩形能贴」而不是整块面板。区间不是试出来的，是**从设计稿截图上量出来的**：

1. 截图里模型外面那圈**橙色包围盒**（建模软件里选中物体显示的框）就是世界包围盒。
   验证方法很硬：**量它的像素宽高比**，与模型真实包围盒的宽高比对比 ——
   `bag_b` 是 `656/969 = 0.6770` vs `0.676/0.998 = 0.6774`，一致就说明可以直接拿它当标尺；
2. 量出红框的四条边（要取**外沿**，描边本身约 6px 宽）；
3. 按橙框归一化：`x_norm = (px - 橙框左) / 橙框宽`，
   `y_norm = (橙框下 - py) / 橙框高` —— **`y` 要上下翻转**，因为 glTF 的 y 朝上、图片的 y 朝下。

```bash
# 帆布包 bag_b：正反两面各一块矩形打印区（同一组区间）
npm run models:fix -- "文创商品模型/bag_b.glb" --out public/models/products/bag_b.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0~0.5" \
  --rename "node_0=bag_body"
# → bag_front 2968 面 / bag_back 2624 面（都可贴） / bag_body 56540 面（侧边与提手，保留）
```

`cos` 这里取 **0.6**（`bag_a` 是 0.7）：软褶多的料子，0.7 会漏掉约 130 面「朝前但被褶子掀斜」的面，
打印区里会出现白斑。判断方法是对比几档阈值下的面数 —— `0.4/0.5/0.6` 三档只差 30 面以内
（说明 0.6 已经收全），而 `0.7` 少了 130 面（说明开始漏），拐点就在 0.6~0.7 之间。

> ⚠️ 裁剪时**必须做顶点去重**（原顶点按 `v<索引>`、交点按 `e<平面id>_<两个端点key>` 建表），
> 否则顶点数会撑成「三角形数 × 3」，文件体积大一倍多（实测 2894 KB vs 800 KB）。
> 补集的正确算法是**凸块分解**（第 i 块 = 满足前 i 个平面、但落在第 i 个平面外侧），
> **不能**把所有平面一起翻过来裁 —— 那样得到的是「对面那个盒子」（= 交集），会丢掉大部分面。
>
> ⚠️ 串联时主循环要**优先取上一步拆出来的几何**（`group.geometry`），
> 不能每次都退回读原始顶点 buffer，否则第一条规则拆出来的正面会被丢掉、数据全乱。

拆出来的零件 UV 会一起补好，**只有 `cup_body` 带着贴图**，`cup_inner` / `cup_bottom`
在部位表里是 `paintable: false`（保留部位），点上去不会贴图案。

四个开关都是**只读模型、只写 `--out` 指定的输出文件**，不会动你手上的原始 GLB。

#### 第四类：自带烘焙贴图的扫描件 / AI 上色件（`--extract-by-color`）

前面三类拆分都要求模型是「白模」——颜色均匀，所以只能靠**几何**认部位。
`fan_b.glb`（团扇）不一样，它有四个反常特征：

| 特征 | 后果 |
| --- | --- |
| 整个模型是**一个单 mesh** | 没有独立对象可拆 |
| **一个连通块、零硬边** | `--island-names` 和 `--extract-inner` 都没有抓手 |
| **已经有 UV**，且是「贴图集的图集坐标」 | 各块之间是分开的 UV 岛，整个面共用一小块纹理坐标 |
| **带一张 4096² 的贴图集**（baseColor + normal + metalRoughness，共 32.9 MB） | 文件 35 MB，首屏会慢 |

几何上无信息可用，但**贴图上有**：白绢、暖色木纹、绿色纹样在贴图里是**不同颜色**。
所以换一条路 —— **采每个三角形 UV 重心处的贴图颜色**来分类：

```bash
# 团扇 fan_b：把「白色绢面」拆出来，其余（雕花边框 + 竹柄）原样保留
npm run models:fix -- "../文创商品模型/fan_b.glb" --out public/models/products/fan_b.glb \
  --extract-by-color "node_0=fan_face;min=150;tol=16" \
  --uv-force "fan_face" \
  --material "fan_body=keep" --material "fan_face=clean" \
  --texture-size 1024 --rename "node_0=fan_body"
# → fan_face 9097 面（可贴）/ fan_body 40903 面（保留）；3266.5 KB
```

四个配套开关（**少一个都出不来可用结果**）：

| 开关 | 干什么 | 为什么需要 |
| --- | --- | --- |
| `--extract-by-color "<源>=<新名>;min=<n>;tol=<n>"` | 按贴图颜色拆出可贴区 | 唯一的抓手 |
| `--uv-force "<零件>"` | **强制重做平面 UV** | 图集 UV 撕不开，必须换成「整张图铺满这一块」 |
| `--material "<零件>=keep\|clean\|wood"` | `keep` = 材质与贴图**原样保留**；`clean` = 清掉贴图留白坯；`wood` = **把木色烤进 GLB** | keep 的那块一个字节都不动；clean 的那块要留白给用户贴图案；wood 给「AI 出的、零贴图、又不该跟着调色板走」的零件（折扇扇骨），**必须配 `keepOriginalParts`** |
| `--texture-size <n>` | 贴图**整数倍盒式降采样** | 4096² → 1024：33 MB → 1.98 MB，GLB 35.17 MB → **3.19 MB** |

⚠️ **判据是「中性浅色」，不是「纯白」** —— 这条错了整件事就废了。
判据要写成「**每个通道都 > `min`**」**而且**「**最大通道差 ≤ `tol`**」：

| 材质 | `min > 200` 只给 `min` 圈得到吗 | 原因 |
| --- | --- | --- |
| 白绢**外表面** | ✅ | 真白 |
| 白绢**内层**（带烘焙阴影） | ❌ 要先放宽到 `min ≈ 150` | 亮度只有 150~200 |
| 木框 / 竹柄 | ❌ 靠 `tol` 挡住 | 暖褐色，**通道差 ≥ 40** |

**为什么「内层」这么要命**：这块绢面是**两层薄片、共用同一份 UV**。
只圈到外表面 → 从扇子背面看是一块白板；两层都圈到 → **贴一次图，正反两面同时上色**。
用户要的「**背面能看到正面图案的反向透影**」**不需要额外做半透明** —— 它就是这个结构的自然结果。

> ⚠️ **阈值必须逐点扫，别只采两三个点就断言「平台」。** 实测 `min` 从 196 扫到 216 是**连续衰减**：
> `200 → 7353 面`（只圈到外表面，背面不上色）、`205 → 1115 面`、`207 → 4 面`。
> 真正稳定的是 **120~180 那一段，恒定 9097 面**。当初只看了 200 和 210 两点就以为「平台在 200~210」，
> 结果整个白绢背面都丢了 —— 所以「面数不变的那一段」是靠**逐点扫描**找出来的，
> 并配一张**目视分类图**（把判出来的面单独上色渲染）交叉验证。

页面侧还要配套两件事（`src/data/modelPresets.ts`）：

```ts
keepOriginalParts: ['body'],        // 这些部位：不套 finish、不套调色板、连材质实例都不换
partFinishes: { face: 'silk' },     // 按部位覆盖 finish —— 扇面走「绢丝」档
// 故意不写顶层 finish → 面板上不出现质感选择器（木框不需要选质感）
```

### 第五类：扇面是**双层**的折扇（`fan_a`）—— 正反面要能各贴一张

混元 3D 出的折扇同样是**一整块软体**（单个 `node_0`、50000 面），但比帆布包多两个坑：

> ⚠️ **2026-10-08 源文件换成了新版**：几何与旧的逐项一致（所以下面三块面数没变），但新版
> **自带 3 张烘焙贴图 + 一套 UV 图集**（底色 15.3 MB / 法线 4.5 MB / 金属粗糙度 5.1 MB，
> `baseColorFactor [0.8,0.8,0.8,1]`）—— 旧版是「零 UV、零贴图、单条灰材质」。
> 因此下面命令比当初多两条**必需**参数：
>   · `--uv-force`：自带的 UV 是**图集布局**（扇面只占贴图里一小块），留着它，用户上传的
>     图案只会采到那一角、还错位，必须换成**平面展开**；
>   · `--material …=clean`：自带烘焙贴图会**染在**用户上传的图案上，而且那张法线图是按旧 UV
>     烘的、换成平面展开后完全对不上 —— 扇面必须清成白坯。
> ⚠️ 默认档是 `{...source}` **浅拷贝、会把贴图一起继承**，「不写 `--material`」不等于「干净」。
> 顶点数也比旧版多（10775 / 11088 / 18021 vs 9378 / 8903 / 14549）：新版自带 UV 的接缝
> 在补 UV 时又被拆了一次点。**面数与包围盒不变就说明拆分正确**，顶点数变化不影响识别。

```bash
npm run models:fix -- "文创商品模型/fan_a.glb" --out public/models/products/fan_a.glb \
  --extract-region "node_0=fan_face_front;axis=+z;cos=0.5;y=0.201~1" \
  --extract-region "node_0=fan_face_back;axis=-z;cos=0.5;y=0.201~1" \
  --uv-force "fan_face_front,fan_face_back" \
  --material "fan_face_front=clean" \
  --material "fan_face_back=clean" \
  --material "fan_ribs=wood" \
  --rename "node_0=fan_ribs"
# → fan_face_front 16821 面（可贴）/ fan_face_back 15907 面（可贴）/ fan_ribs 22150 面（保留，木质）
#   产物 1571.0 KB（旧版 1350.6 KB）
```

**① z 值完全不能当判据。** 扇面是**手风琴式褶皱**，同一片扇面在 z 上起伏交错，
按 z 分层会把扇面撕成满屏锯齿裂口（实测废掉一版）。可靠的是**朝向**：
扇面那两层几乎平摊、法向朝 ±z，扇骨是放射状细条。

**② `y=0.201~1` 是「扇面内弧」这条边界**（绝对高度 `0.13` ÷ 整块包围盒高 `0.646`
归一化得来，不是估的）。扇面内弧在网格里**本来就是三角形断开的地方**，
所以这一刀切下去边界干净、不用试。⚠️ 区间是**相对当前零件包围盒的比例**，
多刀会连锁，改了前面一刀后面必须重算。

**③ 正反两面 = 两个独立零件**，所以「各贴一张不同的图」天然成立；
UV 正面走 `planar-z`、背面走 `planar-z-back`（u 左右翻转），
这样「两面贴同一张图」时从背面看图案也是正的。
（团扇是**一块**扇面两层薄片共用 UV，所以它是「贴一次两面同时上色」，两回事。）

**④ `--material fan_ribs=wood` 必须和 `keepOriginalParts: ['ribs']` 配对。**
AI 模型一个贴图都没有、扇骨是灰的，而网页端的「表面质感」只改 metalness/roughness、
**颜色走调色板**。要让扇骨固定成木色、不跟着扇面底色走，只能把木色**烤进 GLB**
（`wood` = 线性空间的暖木色 `#A87B4F` + `metallic 0` + `roughness 0.7`）再原样保留。
只烤不保留 → 被调色板覆盖；只保留不烤 → 一把灰塑料扇骨。

> ⚠️ `roughness` 为什么是 0.7 而不是更光的 0.48：本项目的影棚环境贴图相当强，
> 扇骨是**一堆法向差不多的薄片**，低粗糙度下它们会**同时**把环境里那块亮面反射进镜头
> → 整簇扇骨发白、木色全被盖掉（实测踩过）。0.7 把高光摊开，底色才压得住。
> 改这个数之前先看 `docs/联调截图/fan_a-贴图验证-*.png`。

> ⚠️ 折扇**不做木纹贴图**，只给纯木色。扇骨是一堆**放射状细条**，UV 走 `planar-z`
> 平面投影（全零件只有一个方向），而木纹要**顺着每根扇骨**才对 —— 放射排布下没有
> 一个方向能对齐，贴上去纹理会横着切过所有扇骨，纯色反而更像真的（真实竹骨折扇
> 本来就接近「均匀色 + 抛光」）。

## 部位命名（重要）

模型必须**按部位拆开**，否则点杯身会把整只杯子（含内壁、把手）一起贴上图案。

**完整的拆分方法、导出设置、命名规则见 [`docs/模型拆分与命名规范.md`](../../docs/模型拆分与命名规范.md)。**

一句话版本：在 Max 里把零件拆成独立对象（或做成多维子材质），命名成下面这些名字即可，配置不用改。

命名格式统一是 **`<商品前缀>_<部位>`**，全小写、下划线分隔：

| 文件 | 可贴图零件 | 保留零件（`paintable: false`） |
| --- | --- | --- |
| 茶杯 · 经典款（`mug_a`，带把手） | `cup_body` 杯身外壁、`cup_handle` 把手 | `cup_inner` 杯口与内壁、`cup_bottom` 杯底 |
| 茶杯 · 直筒款（`mug_b`，**没把手**） | `cup_body` 杯身外壁 | `cup_inner` 杯口与内壁、`cup_bottom` 杯底 |
| 花瓶 ×2（`vase_a` 圆肚 / `vase_b` 细颈） | `vase_side` 瓶身外壁 | `vase_inner` 瓶口与内壁、`vase_bottom` 瓶底 |
| 笔筒 ×2（`holder_a` 圆 / `holder_b` 方） | `holder_side` 筒身外壁 | `holder_inner` 筒口与内壁、`holder_bottom` 筒底 |
| 帆布包 · 托特（`bag_b`） | `bag_front` 包的正面**矩形区**、`bag_back` 包的背面**矩形区** | `bag_body` 侧边与提手 |
| 帆布包 · 一片式（`bag_a`） | `bag_front` 包的正面、`bag_back` 包的背面 | `bag_body` 侧边与提手 |
| 扇子 · 折扇（`fan_a`，**扇面双层**） | `fan_face_front` 扇面·正面、`fan_face_back` 扇面·背面 | `fan_ribs` 扇骨 / 扇柄 / 扇钉（木质） |
| 扇子 · 团扇（`fan_b`） | `fan_face` 白色绢面 | `fan_body` 雕花边框与竹柄 |

> **两个帆布包的正反两面都能贴，而且两面可以贴两张不同的图。**
> 机制上「每贴一次都新建一张贴图实例」，所以先上传图 A 点正面、再上传图 B 点背面，
> 正面那张不会被顶掉（端到端脚本会读回两张贴图实例的 uuid 比对，见
> `--spin 180` 那张反面截图）。
> 两者的可贴范围不同：`bag_a` 是**整块面板**，`bag_b` 是**面板正中的矩形**（按设计稿红框量出来的）。
> `bag_a` 的背面是 AI 软体上用 `--extract-region` 圈出来的，投影走 `planar-z-back`（u 翻转），
> 所以从背面看**不会左右镜像**；`bag_b` 的背面同理。
> 两个包的 `regions` 是**两张不同的表**（`BAG_A_REGIONS` / `BAG_REGIONS`），别混用 ——
> 表里的 `name` 目前一样，但注释各自记着自己的拆分命令，改参数时照着对应的那条改。

> **两个笔筒（圆 / 方）反过来共用同一张 `HOLDER_REGIONS` 表** —— 拆分规则写的是「法向 / 朝向」，
> 与截面形状无关，所以 `holder_b` 直接沿用 `holder_a` 那套零件名，跑 `models:regions` 时会看到
> 「零件与前面的【笔筒·圆】一致，共用 HOLDER_REGIONS」。UV 都走 `cylinder-y`：
> 圆笔筒等比绕筒身一圈；方笔筒**四个面各分到图案的 1/4、跨竖棱连续**。

> 带 `optional: true` 的部位（上表里除 `bag_body` / `fan_ribs` 之外的保留件）
> **模型里可以没有**，自检不会报「缺部位」—— 兼容「不同人拆的粗细不同」：
> 茶杯有人拆内壁、有人不拆，都不影响。

> 前缀可以省（直接叫 `body` / `handle` 也认，配置里两种别名都写了），但**推荐带前缀** ——
> 一个 Max 场景里同时摆几个商品时不会重名。详见命名规范文档第五节。
>
> 想让把手这类零件也能贴图？在 `src/data/modelPresets.ts` 里把那行的 `paintable` 改成 `true` 即可。

## 表面质感（陶瓷为什么看起来不像陶瓷）

模型自带材质只是「白塑料」。真正的**白瓷 = 坯体（偏哑光）+ 上面一层釉（锐利高光）**，
这是**两层反射**，`MeshStandardMaterial` 只有一层，所以做不出来 ——
页面会把商品材质升级成 `MeshPhysicalMaterial`，用 **clearcoat（清漆层）**表达釉面。

不需要你提供任何额外素材，运行起来就是这套：

| 档位 | 用在 | 关键参数 |
| --- | --- | --- |
| 陶瓷釉面 | 经典款茶杯、花瓶、笔筒（默认） | `roughness 0.34` + `clearcoat 1` / `clearcoatRoughness 0.05` |
| 塑料 | 直筒款茶杯（默认） | `roughness 0.4` + `clearcoat 0.6` / `clearcoatRoughness 0.18` —— 高光是**一片油亮的亮带**，不是釉面那种锐利小点 |
| 哑光陶土 | — | `roughness 0.92`、无清漆 |
| 半哑光 | — | `roughness 0.56` + `clearcoat 0.35` |
| 金属 | — | `metalness 1` |
| 帆布 | 帆布包 | `roughness 0.95` + `sheen 1` + **织纹法线贴图**（`repeat 8`） |
| 绢丝 | 团扇白绢面（`partFinishes` 指定） | `roughness 0.62` + `sheen 1` + **细密织纹**（`repeat 22`） |
| 纸质 | 折扇扇面（`partFinishes` 指定） | `roughness 0.8` + **纸纤维法线贴图**（`repeat 9`，凹凸只有帆布的一半） |

> **纸质和哑光陶土怎么分？** 单看数字几乎分不开（`0.8` vs `0.92`），
> 摆在一起只会觉得「两个都是灰扑扑的哑光面」。**纸之所以是纸，肉眼认的是纤维** ——
> 所以纸质档位必须配它自己那张纤维法线贴图，那才是两者的分界线。

> ⚠️ **`sheen > 0` 时必须同时给 `sheenColor`。** three 里 `sheenColor` **默认是纯黑**，
> 而着色器是拿它当绒光项的**系数** —— 只把 `sheen` 从 0 调到 1 是**一点变化都没有**的
> （实测 r177：`new MeshPhysicalMaterial().sheenColor.getHexString() === '000000'`）。
> `finish.ts` 的 `FinishSpec` 因此有一个显式的 `sheenColor` 字段，`applyFinish` 里
> `if (sheen > 0) sheenColor.set(...)`。导出体检会断言 `sheenColorFactor[0] > 0`。

**帆布 / 绢丝 / 纸质这三档多一层程序生成的表面纹理**：`src/three/finish.ts` 里用代码现算
法线贴图，**不依赖任何贴图素材、离线永远能用**。

- **帆布 / 绢丝**走同一张 **128×128 平纹织纹**（`(tx+ty)%2` 决定这一格经纬哪根在上，
  余弦截面 → 高度场 → 中心差分法线），瓦片无缝。两档只差 `roughness` 和**织纹密度**
  （帆布 `repeat 8` / 绢丝 `repeat 22`），所以帆布包上能看见粗斜纹、团扇白绢上是极细的丝织纹。
- **纸质**走另一张 **256×256 纸纤维**：几百根方向集中的细「毛」（两端渐细、横向高斯衰减，
  不是 1 像素硬脊）+ 两三个八度的平滑值噪声（浆块厚薄）+ 极细逐像素毛糙，合成高度场再转法线。
  用**固定种子的确定性伪随机**（mulberry32）—— 换 `Math.random()` 每次刷新纸纹都在变，
  截图就没法对比了。

> ⚠️ **纹理贴图要按 `repeat` 分开缓存**。`Texture.repeat` 是**实例属性**，
> 同一个场景里帆布和绢丝（现在是三种）**共用一个 Texture 实例会互相改 repeat**
> （谁后渲染谁说了算）。做法是：像素算一份（缓存）→ **按 `repeat` 建 Texture**（Map 缓存）。

> 用 `normalMap` 而不是 `bumpMap`，两个原因：① bump 的强度取决于**屏幕空间 UV 导数**，
> 相机一拉远织纹就自己消失；normalMap 是模型空间的，远近一致。
> ② 导出 GLB 时 `bumpMap` 只能写成非标准的 `EXT_materials_bump`（只有 three 自己认），
> `normalMap` 是 glTF 核心 `normalTexture`，到哪儿都认。
> 织纹强度实测：`normalScale 0.02` / `0.09` 在正常视距下**都看不出来**，`0.8` 才明显。

在网页右侧「表面质感」里可以直接切；配置里每个商品有一个 `finish` 默认档。
导出 GLB 时会带上 `KHR_materials_clearcoat` 扩展，**釉面效果一起带走**。

环境反光用的是**程序化影棚**（`src/three/studioEnv.ts`，`PMREMGenerator` 现搭现烘），
不依赖任何 CDN 上的 HDRI 文件，**离线也能出效果**。以前画面正中那条红色警告，
就是旧实现要去网上拉 `studio_small_03_1k.hdr` 失败导致的，现在没有了。

> 想让釉面更「高级」（开片、水渍、微凹凸），才需要额外贴图素材
> （normal map / roughness map）；只要求「像陶瓷」，现在这样就够。

## 导出 GLB 时的注意点

1. **每个零件要有 UV**，或者导出后交给 `npm run models:fix` 自动补。
   贴图靠模型自身的 UV 坐标，完全没有 UV 的零件点上去会提示「没有 UV 坐标」并跳过。
2. **每个零件只有一整块连着的面**。多选/漏选出来的碎块会让人「点 A 部位、B 部位也跟着变」，
   而且补 UV 时包围盒被撑大、图案被挤到一角。`models:fix` 会报出来，并给出
   `--island-names` 修复命令 —— **不用回 Max 重新选面**。
3. **给每个零件一个材质**（标准材质、Base Color 白色）。没给材质会导出成 `fallback Material`
   —— 纯黑 + 全金属，渲染出来是一坨发暗的金属块。
4. 单位、朝向尽量统一（Y 轴朝上），页面会自动按包围盒做等比归一化缩放到约 1.2 个单位。
5. 单文件建议 < 15 MB，否则首屏加载会明显变慢。
6. 只导出商品本体，不要带灯光、相机、辅助对象。
