# 双桥记 · 古桥文创商品 AI 定制器

网页端文创商品 AI 定制：**用户输入文字 → AI 生成图片 → 点击商品表面把图贴上去 → 旋转预览 → 导出 GLB / 下单**。

主题「**双桥记**」取自两座明代古桥 —— **苏州周庄双桥**（世德桥 · 永安桥，一圆一方、俗称钥匙桥）
与 **贵州福泉葛镜桥**（三孔尖拱，三毁三建、俗称豆腐桥）。
界面是一整套宣纸 / 墨 / 朱砂 / 青石的古风样式：**全部视觉集中在 `src/theme.css` 一个文件里**，
改主题不必动底座样式。完整规范（史实出处、取色依据、构图约束、怎么换主题）见
**[`docs/双桥记主题规范.md`](docs/双桥记主题规范.md)**。

底座基于开源项目 [`gorhorvat/product-configurator-3d`](https://github.com/gorhorvat/product-configurator-3d)（React 19 + Three.js + React Three Fiber + Drei + Vite + TypeScript），在其之上增加了 AI 生图、点击选面贴图、贴图微调、导出下单四块能力。底座原有的 README 保留在 `README.base.md`。

> 几何上无抓手，靠 `models:fix --extract-by-color` **按贴图颜色**分区，同时把木质框柄的材质与贴图原样保留）；
> `fan_a` 折扇：**第 5 类模型** —— 同样是 AI 整块软体，但**扇面是前后两层**，
> 靠「朝向 ±z + 高度」两刀拆出正/反两块可贴区（**正反面能各贴一张不同的图**），
> 扇骨用 `--material fan_ribs=wood` **把木色烤进 GLB** 再由 `keepOriginalParts` 原样保留。
> **10 个模型现在全是正式模型**，一个占位件都不剩。
> 把正式模型覆盖同名文件、跑一遍 `models:fix` 即可替换，**配置无需改动**。

### 要换正式模型？先看这份

[**`docs/模型拆分与命名规范.md`**](docs/模型拆分与命名规范.md) —— 在 3ds Max 里怎么拆部位、怎么命名、怎么导出 GLB、
放进哪个目录、导出前检查什么，都在里面。

导出的模型放进去后先跑：

```bash
# 把 Max 导出的半成品修成能用的：补 UV、修材质、烘焙层级，并体检「有没有多选/漏选的面」
npm run models:fix -- "路径/mug_a.glb" --out public/models/products/mug_a.glb
# 再自检：检查 UV + 打印「零件名 ↔ 中文部位」对照表
npm run models:verify
```

`models:fix` 解决的是这条链路上最常见的两个坑：**Max 导出的 GLB 经常没有 UV**（那么贴图完全贴不上去），
以及**没有材质的对象会被导出成纯黑 + 全金属**（`fallback Material`，渲染出来是一坨发暗的金属块）。

它还能**按几何自动拆分**，对手动选面极难处理的情况特别有用：

```bash
# ① 把混进把手的杯底拆出去（按连通性）+ 把杯口内壁拆成独立部位（按法向）
npm run models:fix -- "路径/mug_a.glb" --out public/models/products/mug_a.glb \
  --island-names "cup_handle=cup_bottom,cup_handle" \
  --extract-inner "cup_body=cup_inner"

# ② AI 直接出的「一整块软体」没有硬边、也刷不出分界 → 按「朝向 + 包围盒范围」圈出可贴区
#    帆布包 bag_a：正反两面各圈一块（两条 --extract-region 串联，第二条以第一条剩下的几何为输入）
npm run models:fix -- "路径/bag_a.glb" --out public/models/products/bag_a.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.7;y=0~0.53;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.7;y=0~0.53;z=0~0.5" \
  --rename "node_0=bag_body"

# ③ 可贴区要**严格贴合设计稿上画的框** → 用 x/y 区间收窄成一块矩形（bag_b）
#    区间是拿截图里的橙色包围盒当标尺量出来的，不是试出来的（详见 docs/模型拆分与命名规范.md）
npm run models:fix -- "路径/bag_b.glb" --out public/models/products/bag_b.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0~0.5" \
  --rename "node_0=bag_body"

# ④ 可贴区是「整个回转外壁」、要把内腔和底整个摘掉 → 按法向摘内壁 + 按朝向摘底（笔筒）
#    内壁和外壁沿筒口翻过去、是一整片，靠连通块分不开，只能按「法向朝不朝中轴」拆
#    holder_a（圆）与 holder_b（方）**用同一条命令** —— 规则写的是法向 / 朝向，与截面形状无关
npm run models:fix -- "路径/holder_a.glb" --out public/models/products/holder_a.glb \
  --extract-inner  "node_0=holder_inner" \
  --extract-region "node_0=holder_bottom;axis=-y;cos=0.7;y=0~0.06" \
  --rename "node_0=holder_side"

npm run models:fix -- "路径/holder_b.glb" --out public/models/products/holder_b.glb \
  --extract-inner  "node_0=holder_inner" \
  --extract-region "node_0=holder_bottom;axis=-y;cos=0.7;y=0~0.06" \
  --rename "node_0=holder_side"
```

先加 `--dry` 跑一遍看报告（每块面多大、朝里朝外各多少面、估出来的内壁半径、`--extract-region` 圈到多少面），
确认无误再落盘。`--extract-region` / `--island-names` / `--extract-inner` 都是**只读模型、只写 `--out`**，
不会动你手上的原始 GLB。

## 页面风格：「双桥记」古风主题

一句话：**纸是宣纸、字用宋楷、行动色用朱砂、部位色用青石，装饰是两座桥的长卷。**

| 层面 | 做法 |
| --- | --- |
| 配色 | 取**两桥的公共语汇**（同属明万历、同为青石砌筑、都跨江）→ 宣纸 / 墨 / 朱砂 / 青石 / 水色 / 山色 / 黛瓦 |
| 字体 | 正文宋体、标题与印章楷体；**只用系统字体，零网络字体**（与 `studioEnv.ts` 拒用 CDN 同一个理由：离线可用） |
| 面板 | 半透宣纸 + 墨线描边 + 纸纹帘纹，卡片标题前一道**朱砂签条** |
| 按钮 | 主行动 = 朱砂（像盖印）；部位按钮 = 青石；危险操作 = 深赭 |
| 装饰 | `BridgeBackdrop` 底部水墨长卷：左半**周庄双桥**（圆拱 + 方洞、交叉成钥匙形），右半**葛镜桥**（二墩三孔尖拱、绝壁借礁） |
| 题签 | 工具栏左端一枚朱砂印，图样是两桥的合体：桥面之下圆拱 + 方洞 + 尖拱并列 |
| 画底 | 「配置 → 画底」8 个预设（墨青 / 青石 / 暮山 / 赭石 / 黛瓦 / 焦墨 / 宣纸 / 绢本）；**装饰线颜色随画底明暗自动翻转** |
| 桥志 | 工作台底部的折卡，写明两桥的年代、出资人、尺寸、题名、传说与文保级别 |

⚠️ **改主题只动 `src/theme.css`**。`App.css` / `studio.css` 现在只负责结构（布局、间距、
状态类名、响应式断点），它们那套暗色玻璃配色是被主题层覆盖掉的原始外观。
`theme.css` 在 `App.tsx` 里**必须最后 import**，提到前面整个界面就会退回暗色玻璃。

⚠️ 装饰长卷的构图受**两块面板的遮挡**限制：左侧「配色」280px、右侧工作台 350px，
在 1440 宽下换算到长卷 viewBox，可见区只有 `x ≈ 294 ~ 846`。
所以两座桥全部排在 `x 320 ~ 820`。**改面板宽度或改长卷高度后，必须重新截图核对。**

## 关键机制：贴在哪个部位，由「名字」决定

整套贴图链路分两层。

### 第一层：点中了哪个面（Raycaster，不依赖命名）

1. 用户在 ①/② 里拿到一张图（AI 生成或本地文件），存进 `textureStudio` 的 pending 槽位；
2. 界面提示「请点击商品要贴图的面」，并把光标切换成十字；
3. 用户点击 Canvas → `SurfacePicker` 用 `THREE.Raycaster` + `setFromCamera` 从屏幕坐标反推；
4. 射线只对 `name="product-root"` 的商品节点做 `intersectObjects([root], true)`，取第一个命中的 mesh；
5. 贴图按 GLTF 约定设置 `colorSpace = SRGBColorSpace` + `flipY = false`，与模型自带贴图保持一致。

### 第二层：这个面属于哪个部位（`three/regions.ts`）

模型在 3ds Max 里按部位拆开并命名后，`modelPresets.ts` 的 `regions` 表把零件名映射成中文部位：

- **点杯身就贴杯身，点把手就贴把手**，各自独立、互不牵连；
- 命中「保留部位」（如杯口内壁）会明确提示并拒绝贴图，不会静默乱贴；
- 右侧工作台多出一排**「可贴图部位」按钮**，不用在 3D 模型上费劲找零件；
- 名字对不上时，面板会直接把**模型里的真实零件名**列出来，方便补配置。

命名匹配查两个通道：**对象名**（分离成独立对象）与**材质名**（多维子材质），
按「完全一致 → 去 `_1` 后缀 → 去分隔符 → 按分词」四级优先级匹配，详细规则见
[`docs/模型拆分与命名规范.md`](docs/模型拆分与命名规范.md)。

一堆零件同时被贴图时，只有在材质**还被范围外网格共用**的情况下才 `clone()`；
同一个原材质只克隆一次，多个零件共用同一份克隆体和同一张贴图实例。

「移除贴图」按后进先出逐次回滚，每次都能精确还原成模型自带外观。

**贴完一处还能接着贴别的部位**：第一次贴图之后，「可贴图部位」按钮不会消失，
可以继续用同一张图贴到别的部位（内部沿用最近一张图，不需要重新上传）。
此时 3D 视图里的点击不生效 —— 避免用户转着看模型时被误贴，要贴就点按钮。

### ⚠️ 导出前必须洗掉「UI 状态」

底座的交互会把**悬停加亮（`color` ×1.2）**和**选中高亮（`color` 偏向黄色 + `emissive` 橙色）**
直接写进 `material.color` / `material.emissive`。这些是**屏幕上的显示状态**，不是商品本来的颜色。

如果不处理，`GLTFExporter` 会把它们原样写进 GLB：实测 `baseColorFactor` 变成 `[1.13, 1.07, 0.80]`、
`emissiveFactor` 变成 `[1, 0.40, 0]` —— 商品拿到别的软件里打开会整体偏亮偏黄。

所以：

- `BodyTintedConfigurator` / `PerMaterialConfigurator` 在写高亮色的同时，把**干净颜色**记进
  `material.userData.__cleanColor`；
- `ExportPanel` 调 `stripUiTint(root)` 在导出前还原、导出后恢复（`three/surfacePainter.ts`）。

**新增任何改 `material.color` 的交互时，都要照这个模式记一份干净值**，否则导出会脏。

底座的「改色」功能（`modelPresets.ts` 里的 materials 配置 + `material.color`）保持原样未动。
10 个文创商品统一用 `colorMode: 'body'`，所有 mesh 都映射到 `materials[0].id`，本来就不依赖材质名匹配。
（以后想「按部位分别改色」，把 `colorMode` 改成 `'per-material'`、`materials` 的 `id` 写成部位名即可，
底座的 `PerMaterialConfigurator` 已经按材质名匹配了。）

### 部位命名表（`regions`）

每个商品带一张「零件名 ↔ 中文部位」的表。模型里的零件名对上哪一行，就归到哪个部位。

命名格式统一为 **`<商品前缀>_<部位>`**（`cup_body` / `vase_neck` / `bag_front` …），
配置表里每个部位都同时写了**带前缀**和**不带前缀**两个别名，所以两种命名都能精确匹配：

| 商品 | 可贴图部位 | 保留部位（点了会被拒绝） |
| --- | --- | --- |
| 茶杯 ×2 | `cup_body` 杯身外壁、`cup_handle` 把手 | `cup_inner` 杯口与内壁、`cup_bottom` 杯底 |
| 花瓶 ×2（`vase_a` 圆肚 / `vase_b` 细颈） | `vase_side` 瓶身外壁 | `vase_inner` 瓶口与内壁、`vase_bottom` 瓶底 |
| 笔筒 ×2（`holder_a` 圆 / `holder_b` 方） | `holder_side` 筒身外壁 | `holder_inner` 筒口与内壁、`holder_bottom` 筒底 |
| 帆布包 · 托特（`bag_b`） | `bag_front` 包的正面**矩形区**、`bag_back` 包的背面**矩形区** | `bag_body` 侧边与提手 |
| 帆布包 · 一片式（`bag_a`） | `bag_front` 包的正面、`bag_back` 包的背面 | `bag_body` 侧边与提手 |
| 扇子 · 折扇（`fan_a`，**扇面双层**） | `fan_face_front` 扇面·正面、`fan_face_back` 扇面·背面（**两面可各贴一张**） | `fan_ribs` 扇骨 / 扇柄 / 扇钉 —— **木质，木色烤进 GLB 且整块保留** |
| 团扇（`fan_b`） | `fan_face` 扇面（白绢） | `fan_body` 扇框与竹柄 —— **且整块保留模型自带材质** |

> **团扇是「第 4 类模型」：自带烘焙贴图的扫描件**（AI 上色件 / 扫描件都属于这类），
> 它和上面 9 个白模的玩法不太一样：
> * 整块 50000 面、**只有 1 个连通块**、但自带 UV 和一张 4096² 的贴图集（木纹 / 雕花边 / 白绢全烤在同一张图上）。
>   所以「哪块面是白绢」既不能靠连通性、也不能靠朝向，只能**按贴图颜色认**：
>   `--extract-by-color "node_0=fan_face;min=150;tol=16"` —— 白绢是**中性浅色**（每通道 > 150 且通道差 ≤ 16），
>   木头是暖色（通道差 ≥ 40），分得干干净净。
> * 白绢本身是**前后两层薄片**，而且共用同一份 UV。所以贴上去的图案**正反两面同时呈现** ——
>   这就是「从扇子背面也能看到正面图案的反向透影」，**不需要额外做半透明**。
>   ⚠️ 因此阈值必须把两层都圈进来（只写 `min=200` 只能圈到外表面那 7353 面，背面那层会留在扇框里、
>   背面就看不到图案了）。
> * 扇框与竹柄走 `--material fan_body=keep`：**贴图、法线图、metallic/roughness 一个都不动**；
>   网页端再靠 preset 的 `keepOriginalParts: ['body']` 保证「不套质感、不套调色板、不进全彩模式」。
> * 贴图集 4096²、三张共 33 MB，用 `--texture-size 1024` 压到约 2 MB（整个 GLB 3.2 MB）。
>
> **`keepOriginalParts` / `partFinishes` 两个新字段**（`ModelPreset` 上）：
>
> ```ts
> keepOriginalParts: ['body'],        // 这些部位保留模型自带材质：不套 finish / 不套调色板 / 贴图一个不动
> partFinishes: { face: 'silk' },     // 按部位指定质感（键是 regions 里的部位 id）
> ```
>
> 团扇是**白绢面 + 木质扇框**两种材质凑在一个商品上，一个 `finish` 盖不住，才需要它俩。
> 注意团扇**故意不写顶层 `finish`** —— 于是面板上不出现「表面质感」选择器，
> 用户不会把绢面误调成陶瓷釉面。

> **两个帆布包的正反两面都能贴，而且两面可以各贴一张不同的图。**
> 每贴一次都会新建一张贴图实例，所以「上传图 A 点正面 → 上传图 B 点背面」得到的是两张不同的图案，
> 正面那张不会被顶掉。两者的**可贴范围不同**：`bag_a` 是整块面板，`bag_b` 是面板正中的矩形
> （拿着设计稿截图上的红框、以橙色包围盒当标尺量出来的 `x=0.12~0.915` / `y=0.10~0.42`）。
> 背面都是 AI 软体上用 `--extract-region` 圈出来的，投影用 `planar-z-back`（u 翻转）
> —— 从背面看**不会左右镜像**。
> 两个包用**两张不同的 `regions` 表**（`BAG_A_REGIONS` / `BAG_REGIONS`），别混用。
>
> **两个笔筒（圆 / 方）反过来共用同一张 `HOLDER_REGIONS` 表** —— 拆分规则写的是「法向 / 朝向」，
> 与截面形状无关，所以 `holder_b` 直接沿用 `holder_a` 那套零件名。UV 都走 `cylinder-y`：
> 圆笔筒等比绕筒身一圈；方笔筒**四个面各分到图案的 1/4、跨竖棱连续**（面心基本不拉伸，
> 越靠竖棱越被拉开 —— 圆角半径约是半宽的 24%，最边缘约 1.6×）。

**「可贴 / 保留」是配置里的一行数据，改一个词就换**：

```ts
{ id: 'handle', name: '把手', match: ['cup_handle', 'handle'], paintable: true },
//                                                              ↑ false = 锁住这个部位
```

`optional: true` 表示「模型里可以没有这个部位」，用来兼容不同人拆的粗细不一样
（比如只拆了「杯体 + 把手」、没拆杯口内壁，自检就不会报缺部位）。

**改名字不用改代码，只改这张表**（`src/data/modelPresets.ts` 里的 `regions`）。
空着不写就等于「没按部位拆」，会退化成「点哪儿贴哪儿（只贴命中的那一个 mesh）」。
自己定了别的名字，跑 `npm run models:regions` 生成配置骨架自己粘回去即可。

正式的拆分方法 / 导出设置 / 命名规则见 [`docs/模型拆分与命名规范.md`](docs/模型拆分与命名规范.md)。

> 现在 `public/models/products/` 里**正式模型有 9 个**：`mug_a` / `mug_b`（茶杯）、`bag_a` / `bag_b`（帆布包）、
> `holder_a` / `holder_b`（笔筒）、`vase_a` / `vase_b`（花瓶）、`fan_a`（折扇）、`fan_b`（团扇，自带烘焙贴图的扫描件）
> —— **10 个商品位全是正式模型，占位件已全部退役**（`scripts/make-placeholder-models.mjs` 里那批
> 几何占位件只留作历史参考，**现在跑它会覆盖正式模型，别跑**）。
> （另外目录里还躺着两个撤下来的冰箱贴 `magnet_a` / `magnet_b`，没被任何商品引用 —— `models:verify` 会提示，
> 那不是错误。）

底座自带的 4 个示例配置（Aline / Umber ×2 / PS5）保留在 `LEGACY_PRESETS` 常量里，
但因为它们的模型文件合计约 70 MB（本机网络拉取不稳定，`git clone` 多次中断），
没有放进默认的 `MODEL_PRESETS`，避免下拉框里出现「点了就 404」的选项。
把底座仓库的 `public/models/` 拷进来后，改成 `[...LEGACY_PRESETS, ...WENCHUANG_PRESETS]` 即可启用。

## 贴图扭曲 / 贴错位置怎么办

**贴错了位置**（点杯身结果把手也被印上、或者点哪儿都只贴一小块）：

1. 先跑 `npm run models:verify`，看「零件名 ↔ 中文部位」对照表 —— 多半是模型里的名字和 `regions` 表对不上；
2. 名字对不上时，网页的「可贴图部位」区域会直接把模型里的真实零件名列出来，照着改 `regions` 即可（只改数据）；
3. 如果模型是整块一个 mesh，那贴图必然覆盖整块 —— 需要在 Max 里按部位拆开。见
   [`docs/模型拆分与命名规范.md`](docs/模型拆分与命名规范.md)。

**图案被拉伸/撕裂**（UV 本身的问题）：

1. 打开浏览器控制台，确认 `mesh.geometry.attributes.uv` 存在（没有会直接提示「该部位没有 UV 坐标」）；
2. 回建模软件对**该部位**重新做一次 UVW 展开，再导出 GLB 覆盖同名文件；
3. 扇子（`fan_a` / `fan_b`）最容易出问题，因为扇面是薄壳结构，重点重跑扇面那一块；
4. 轻微的错位可以先用工作台 ③ 的 偏移 / 平铺 / 旋转 滑块补偿。

## 表面质感（陶瓷釉面为什么之前出不来）

左侧 **Colors** 面板下半部分有一排「**表面质感**」按钮，按商品给了默认档：

| 档位 | 用在哪 | 关键参数 |
| --- | --- | --- |
| **陶瓷釉面**（默认给经典款茶杯 / 花瓶 / 笔筒） | 白瓷、青瓷 | `roughness 0.34` + **`clearcoat 1 / clearcoatRoughness 0.05`** |
| **塑料**（默认给直筒款茶杯） | 注塑塑料（PP / ABS） | `roughness 0.4` + `clearcoat 0.6 / clearcoatRoughness 0.18` —— 高光是**一片油亮的亮带**，而不是釉面那种锐利小点 |
| 哑光陶土 | 素坯、粗陶 | `roughness 0.92`，无清漆层 |
| 半哑光 | 哑光漆面 | `roughness 0.56` + 轻微清漆 |
| 金属 | 金属徽章、五金件 | `metalness 1 / roughness 0.28` |
| **帆布**（默认给帆布包） | 布料 | `roughness 0.95` + `sheen 1` + **程序生成的织纹法线贴图** |
| **绢丝**（默认给团扇的白绢面） | 绢 / 绸 | `roughness 0.62` + `sheen 1 / sheenRoughness 0.3`（丝光比帆布「光」得多）+ 更细密的织纹（`repeat 22` / 凹凸只有帆布一半） |
| **纸质**（默认给折扇的扇面） | 宣纸 / 卡纸 | `roughness 0.8`，无清漆层 + **程序生成的纸纤维法线贴图**（`repeat 9`）—— 纸和「哑光陶土」单看数字几乎分不开，**纤维纹理才是两者的分界线** |

> ⚠️ **加新档位时别忘了另外两处**（都不在 `finish.ts` 里）：
> ① `scripts/e2e-finish.mjs` 的档位清单是**写死的**，不同步就会「新档位静默不被回归覆盖」
> （加「纸质」时踩过一次：跑出来只有 7 档、还全绿）；
> ② `check:export` 的 `expectNormalTexture` 断言要用 `victims`（排除 `keepOriginalParts` 的部位），
> 否则折扇这种「扇面有程序纹理、扇骨是纯色木」的混合模型会误报。

> ⚠️ **`sheen` 必须配 `sheenColor`，否则等于没设。**
> three 的 `MeshPhysicalMaterial.sheenColor` **默认是纯黑**（实测 r177：`new MeshPhysicalMaterial().sheenColor.getHexString()` = `'000000'`），
> 而着色器里绒光是拿它当系数乘上去的 —— 黑色绒面 = 完全没有绒光，
> 导出时也会写成 `sheenColorFactor: [0,0,0]`。这个坑实测踩过：帆布那档从一开始就只写了 `sheen: 1`，
> **绒光一直是空的**（只在 `check:export` 里加了「`sheenColorFactor` 必须 > 0」的断言才暴露出来）。
> 现在 `FinishSpec.sheenColor` 是显式字段，`applyFinish` 在 `sheen > 0` 时一定会写它。
>
> 另外**织纹法线贴图按 `repeat` 分开缓存**：`repeat` 是贴在 `Texture` 实例上的属性，
> 而同一个模型里可能有两种布（绢面 + 帆布），共用一张贴图的话后设的会把前面的 `repeat` 改掉。

**帆布那一档还多一层织纹**：`src/three/finish.ts` 里用代码现算一张 128×128 的平纹织法法线贴图
（`(tx+ty)%2` 决定这一格经纬哪根压在上面，余弦截面 → 高度场 → 中心差分法线），瓦片无缝、`repeat 8`。
所以帆布包上能看见斜纹布的凹凸，**同样不需要任何 texture 素材**。

> 这里用 `normalMap` 而不是 `bumpMap`：① bump 的强度取决于**屏幕空间 UV 导数**，相机拉远织纹会自己消失，
> normalMap 是模型空间的，远近一致；② 导出 GLB 时 `bumpMap` 只能写成非标准的 `EXT_materials_bump`
> （只有 three 自己认），`normalMap` 是 glTF 核心 `normalTexture`，到哪儿都认。
> 强度实测：`normalScale 0.02` / `0.09` 在正常视距下都看不出来，`0.8` 才明显。

**为什么陶瓷需要专门做一层**：GLB 里一个材质只有 `metallic` / `roughness` 两个数字，
而真瓷器的观感来自**两层反射** —— 下面一层是高粗糙的坯体，上面一层是烧出来的釉（又小又亮的锐利高光）。
`MeshStandardMaterial` 只有一层，做不出这种双层效果，所以这里把材质升级成
**`MeshPhysicalMaterial`**，用它的 **clearcoat（清漆层）** 来表达「釉」。

**为什么之前"没体现出来"**：两个原因叠加 ——

1. 材质层没做（`roughness 0.65` 的白模，看着像没上釉的素坯）；
2. **环境贴图没加载上**。釉面/金属的亮度几乎全部来自**反射周围环境**，
   只靠几盏平行光只会得到几个死板的小亮点。而底座用的是 drei 的
   `<Environment preset="studio" />`，它要从 CDN 拉 `studio_small_03_1k.hdr` ——
   **离线就拉不到**，画面正中还会弹一条「环境贴图加载失败」的红色提示。

现在环境贴图改成 **`src/three/studioEnv.ts` 里用代码现搭现烘**（`PMREMGenerator.fromScene`）：
零外部资源、离线永远可用、不吃网络。影棚布光是「1 个顶部柔光箱 + 2 根细竖条灯 + 1 根背光 + 1 块地面补光板」——
**竖条灯是刻意做细的**，因为灯越窄，反射到圆柱面上拉出的高光带越锐利，
那是"这是上了釉的瓷器、不是塑料"最直接的一条视觉线索。

> ⚠️ **踩过的坑（改代码时注意）**：three 的渲染器在
> `material.envMap === null && scene.environment !== null` 时，每一帧都会用
> `scene.environmentIntensity` **覆盖** `material.envMapIntensity`。
> 也就是说「按质感档位给不同的反射强度」在只设 `scene.environment` 的路子下是做不到的，
> 必须把烘好的贴图**挂到材质自己的 `envMap` 上**（`three/finish.ts` 的 `applyEnvironment`）。
> 贴图由 `Scene.tsx` 烘好后用 prop 下发，因为 `<Canvas>` 会另起渲染树，外部 context 不保证穿透。

想自己调：跑 `npm run e2e:finish`，它会逐个点档位并裁出商品特写，横着比一眼就能看出区别
（`docs/联调截图/27-表面质感-*.png`）。想核对真实数字：`npm run check:material`。

**换商品对照**：加 `--model bag_b`（`node scripts/e2e-finish.mjs 40-x --model bag_b`）。
用途是验证「**同一档质感在不同商品上是不是真的同一档**」——
比如 `bag_a` 与 `bag_b` 的帆布档，跑完读回的材质快照逐项相等
（`roughness 0.95` / `sheen 1` / `hasWeave true` / `weaveScale 0.8` / `envMapIntensity 0.55`），
对照图见 `docs/联调截图/41-帆布质感对照-bag_a与bag_b.png`。

## 灯光与曝光（商品发白、过曝怎么办）

工具栏右侧有一个 **☀ 灯光与曝光** 按钮，里面 5 档滑块可以直接调：

| 滑块 | 作用 | 默认 |
| --- | --- | --- |
| 整体曝光 | `renderer.toneMappingExposure`，全局乘数，**觉得整体偏亮/偏暗先动这一档** | 0.85 |
| 环境反光 | 影棚环境贴图强度，陶瓷/釉面/金属感商品主要靠它 | 1.00 |
| 主光 | 右上前方平行光 | 0.40 |
| 补光 | 左后方辅助平行光，压暗部 | 0.18 |
| 环境光 | 无方向底光，避免背面全黑 | 0.04 |

**为什么需要调**：底座原本的光照是按 PS5 手柄调的（深色外壳），那套参数放在白瓷、浅色布料上会严重过曝。
以「花瓶·细颈」为例，用底座原参数实测：

| 指标 | 底座原参数 | 当前默认 | 说明 |
| --- | --- | --- | --- |
| 商品像素平均亮度 | 234.1 / 255 | **196.3** | 接近顶格 → 有层次 |
| 亮度 > 240 的像素占比 | 46.2% | **8.7%** | 近一半表面丢细节 → 只剩高光点 |
| 亮度 > 250 的像素占比 | 18.6% | **0%** | 纯白死区 → 完全消失 |
| 最高亮度 | 254 | 247 | 高光保留渐变 |

对比见 `docs/联调截图/06-灯光过曝（调整前）.png` 与 `07-灯光修复后.png`：
调整前瓶身是一块没有体积感的白块，调整后能看清圆柱面的明暗渐变、肩部转折和瓶颈轮廓。

调参建议：**白瓷、浅色帆布先降「整体曝光」**；**想让釉面更"亮面"就调高「环境反光」**
（釉面的高光几乎全部来自环境反射，对平行光不敏感）。改完点「恢复默认灯光」可一键回到上表默认值。

> 「环境反光」会同时影响两处：没挂 envMap 的材质走 `scene.environmentIntensity`，
> 商品材质则按「质感档位权重 × 这一档」写进 `material.envMapIntensity` —— 两条路互不打架。

`--extract-region` 的报告长这样（帆布包，一整块软体上**正反两面各圈一块**）：

```
输入  bag_a.glb  1368.3 KB
      共 1 个 mesh 实例

  · node_0：按「朝向 +z(cos≥0.7) y=0~0.53 z=0.5~1」圈出 5822 面 → bag_front，47224 面留在 node_0
      整块尺寸 0.678 × 1.043 × 0.286（x/y/z 的区间都是相对它自己的包围盒按比例计的），按 2 个平面切开（边界是直线，不是锯齿）
  · node_0：按「朝向 -z(cos≥0.7) y=0~0.53 z=0~0.5」圈出 4548 面 → bag_back，47016 面留在 node_0
      整块尺寸 0.678 × 1.043 × 0.279（x/y/z 的区间都是相对它自己的包围盒按比例计的），按 2 个平面切开（边界是直线，不是锯齿）
  bag_front         5822 面  0.673 × 0.550 × 0.077  补 UV（planar-z）
                  ↳ 从 node_0 拆出（3181 顶点）
  bag_back          4548 面  0.674 × 0.550 × 0.110  补 UV（planar-z-back）
                  ↳ 从 node_0 拆出（2499 顶点）
  bag_body         47016 面  0.678 × 1.043 × 0.270  补 UV（planar-z）
                  ↳ 从 node_0 拆出（27298 顶点）

```

> 第二条规则**以第一条剩下的几何为输入**（所以报告里的第二行「整块尺寸」是补集的包围盒）。
> 区间是**相对当次输入几何自己的包围盒**归一化的 —— 串联时要注意这一点。
>
> 背面用 `planar-z-back` 而不是 `planar-z`：观察点在 -Z 时 X 轴在屏幕上左右相反，
> 不翻 `u` 的话贴上去的文字/印章会**左右镜像**。
>
> 切出来的新边会多出一些面（`5822 + 4548 + 47016 = 57386` > 原本的 50000），是正常的。
> 顶点数能压到 3181 / 2499 / 27298，靠的是裁剪时的**顶点去重表**（原顶点按 `v<索引>`、交点按 `e<平面id>_<两端点>`），
> 不做的话会变成「三角形数 × 3」，文件体积大一倍多。

`bag_b`（托特包）用的是同一个开关，但多给了 `x` 区间，把可贴区收成**面板正中的一块矩形**
—— 区间是拿设计稿上的红框量出来的：

```
输入  bag_b.glb  1368.3 KB
      共 1 个 mesh 实例

  · node_0：按「朝向 +z(cos≥0.6) x=0.12~0.915 y=0.1~0.42 z=0.5~1」圈出 2968 面 → bag_front，52038 面留在 node_0
      整块尺寸 0.676 × 0.998 × 0.403（x/y/z 的区间都是相对它自己的包围盒按比例计的），按 5 个平面切开（边界是直线，不是锯齿）

      整块尺寸 0.676 × 0.998 × 0.400（x/y/z 的区间都是相对它自己的包围盒按比例计的），按 5 个平面切开（边界是直线，不是锯齿）
  bag_front         2968 面  0.537 × 0.319 × 0.093  补 UV（planar-z）
                  ↳ 从 node_0 拆出（1682 顶点）
  bag_back          2624 面  0.537 × 0.319 × 0.093  补 UV（planar-z-back）
                  ↳ 从 node_0 拆出（1551 顶点）
  bag_body         56540 面  0.676 × 0.998 × 0.398  补 UV（planar-z）
                  ↳ 从 node_0 拆出（34139 顶点）

输出  public/models/products/bag_b.glb  1899.0 KB
```

> `bag_front` 的包围盒 `0.537 × 0.319` 正好等于红框换算出的区间宽度
> （`0.915-0.12 = 0.795` × 模型宽 `0.676` = `0.537`；`0.42-0.10 = 0.32` × 模型高 `0.998` = `0.319`）
> —— 可以直接用这个等式验证「量出来的框是不是真的对上了」。

`models:verify` 的输出长这样（正式模型 mug_a）：

```
正常  mug_a.glb  mesh=4  带UV=4/4  1140.3 KB
      零件：cup_bottom, cup_handle, cup_inner, cup_body
      部位  杯身外壁（可贴） ← cup_body  1 个零件  [精确匹配]
      部位  把手（可贴） ← cup_handle  1 个零件  [精确匹配]
      部位  杯口与内壁（保留） ← cup_inner  1 个零件  [精确匹配]
      部位  杯底（保留） ← cup_bottom  1 个零件  [精确匹配]
```

它跑的就是网页端同一份代码（`GLTFLoader` 解析 + `three/regions.ts` 的名字匹配），所以自检通过，网页里就一定能认出来。

`models:regions` 是给「模型改过分区」准备的：它读每个模型的实际零件名，对照现有命名表，
沿用你已经写好的中文名和「可贴 / 保留」设置，只把新出现的零件标成 `TODO`。
输出的常量名会**自动沿用源码里现有的**（两个茶杯共用一个 `CUP_REGIONS`，不会拆成两个），
所以粘回去时连 `regions:` 的引用都不用动。脚本只读不写 —— 粘贴这一步由人确认，顺便当一次复核。

> 就能得到两张不同的图案，先贴的那张不会被顶掉。**连续贴图**时「可贴图部位」按钮不会消失；
> 但此时在 3D 视图里直接点模型**不会**贴图（避免转着看模型时被误踩），要贴就点按钮。

**帆布包 `bag_b`（托特包）跑的是同一组 16 项**（`--model bag_b`），全部通过。
它和 `bag_a` 的差别只在**可贴区的大小**：`bag_b` 的可贴区是面板正中的矩形，
断言里额外看的是「图案没有溢出到矩形之外」—— 放大截图里能看到打印区四条边都是直线，
矩形外的包面保持干净的帆布底色。

**笔筒 `holder_a`（圆）/ `holder_b`（方）**各跑一遍 `npm run e2e:paint -- --model holder_a` / `--model holder_b`，**各 11 项全部通过**：

| 项 | 结果 |
| --- | --- |
| 零件 | `holder_side` / `holder_inner` / `holder_bottom` 三个 —— 两个笔筒**零件名完全一样**（方截面的那套几何判据和圆的等价），所以**共用同一张 `HOLDER_REGIONS` 表** |
| 「可贴图部位」按钮 | `筒身外壁 / 筒口与内壁(保留) / 筒底(保留)` —— **只有一处可贴** |
| 材质是陶瓷釉面档 | `MeshPhysicalMaterial`，`clearcoat = 1`、`roughness = 0.34`（与茶杯釉面档逐项相等） |
| 点「筒身外壁」 | `holder_side` 贴上；**`holder_inner` 与 `holder_bottom` 都保持无贴图** —— 用户要求「只对侧面外壁贴图」，内腔和筒底一点没被碰到 |
| 颜色干净 | 三个零件 `color` 都是 `#ffffff`、`emissive` 都是 `#000000` |
| 导出 GLB 的材质 | 3 个材质，只有 `holder_side` 带 `baseColorTexture`；釉面带 `KHR_materials_clearcoat`，`clearcoatFactor = 1`（`npm run check:export -- --model holder_a` / `--model holder_b` 各 **5/5 通过**） |

前几项是关键：它证明贴图**真的只作用在外壁上**，内壁和杯底一点没被碰到。

**花瓶 `vase_a`（圆肚）/ `vase_b`（细颈）**跑的是同一组 11 项（`--model vase_a` / `--model vase_b`），
**各 11 项全部通过**；零件名与笔筒一一对应：`vase_side`（瓶身外壁，可贴）/
`vase_inner`（瓶口与内壁，保留）/ `vase_bottom`（瓶底，保留），**共用一张 `VASE_REGIONS`**。

> ⚠️ 花瓶和笔筒**只有一处参数不同**：摘底那刀 `y` 的上界。笔筒 `0~0.06` 就够，而花瓶的底是
> **两级**的（外圈一圈朝下的环 + 中心一块位置最低的底盘，分布在 5%~11% 高度这段），
> 照抄 `0.06` 会**正好切在中间**、把半个凹底留在可贴区 —— 症状是「点外壁贴图，瓶底看不见的凹面也变色」。
> **花瓶要用 `0~0.12`。** 这个值是用 `npm run models:layers -- vase_a` 按高度分层量出来的
> （看每一层还剩多少「朝下」的面）—— **别沿用别的商品，现场量**。
> 另外 `vase_bottom` 会报「2 块互不相连的面」—— 那是**模型真实的几何结构**（两级底），
> 不是拆分多选 / 漏选；两块都朝下、都属于瓶底、都标保留，不用处理。
>
> 跑探针时你会看到 `vase_side` 里**也**还留着一批「朝下↓」的面（`vase_a` 1330 面 / `vase_b` 451 面），
> 这里**不是**底没摘干净 —— 逐层看半径（探针会连「同层外壁 / 内壁半径」一起打印）：
> 大头在**最顶层瓶口**（`vase_a` 1259 面、半径中位 0.174，同层外壁 0.198 内壁 0.122；
> `vase_b` 414 面、半径中位 0.113，同层外壁 0.096 内壁 0.088），两个都**大于同层内壁**，
> 也就是落在**外扩口沿的下表面**上 —— 从侧下方看得见，属外壁，**留着才对**
> （摘掉反而会在瓶口留一圈白边）。剩下几十面在底部、半径 ≈ 同层外壁，是壁底交界的倒角。
> 口径：**半径比同层 `_inner` 小才是内壁翻边该摘。**
