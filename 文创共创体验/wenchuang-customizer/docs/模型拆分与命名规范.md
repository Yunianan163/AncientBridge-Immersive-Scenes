# 模型拆分与命名规范

这份文档解决一件事：**在 3ds Max 里怎么拆、怎么命名，导出的 GLB 放进去之后，网页才能精确地把贴图贴到你想要的那一块，而不是整只杯子。**

---

## 零、整体流程

```
① 混元 3D 生成模型  →  ② 导出 GLB  →  ③ 3ds Max 里按部位拆分 + 命名
                                             ↓
⑥ 用户就能按部位贴图了  ←  ⑤ 覆盖进 public/models/products/  ←  ④ 导出 GLB
                                ↑
                    npm run models:fix   ← 自动补 UV + 修材质 + 体检
```

导出之后过一遍这两条命令，问题基本都能提前发现：

```bash
npm run models:fix -- "D:/.../文创商品模型/mug_a.glb" --out public/models/products/mug_a.glb
npm run models:verify
```

- **`models:fix`** 负责把 Max 导出的「半成品」修成能用的：**补 UV**（没有 UV 就完全贴不上图）、
  **修材质**（没有材质的对象会被导出成纯黑 + 全金属）、**烘焙节点层级**，顺便做一次体检。
  它还会告诉你「哪个部位里混进了不属于它的面」——这是拆分时最常犯的错。
- **`models:verify`** 做最终自检：文件在不在、能不能解析、UV 全不全、零件名和部位表对不对得上。

> 如果你在 Max 里做完了 UVW 展开，`models:fix` 会**原样保留**你的 UV，只修材质和体检，不会覆盖。
> 想强制重新生成就加 `--force`。

**关键结论先说：如果你按第六节的名字命名（`cup_body` / `cup_handle` / `vase_side` /
`holder_side` / `bag_front` …），代码一行都不用改。** 这套名字已经写进
`src/data/modelPresets.ts` 的 `regions` 表了，连「哪个部位能贴、哪个保留」都定好了。

如果你要自己定名字、或者调整分区方案，也不用找我改代码 —— 跑 `npm run models:regions` 生成配置自己粘，见第八节。

## 二、为什么必须拆

现在的贴图逻辑是：**射线打到你点的那个零件上 → 把这个零件所属的「部位」整块贴上。**

如果杯子是一个整体 mesh，那么点杯身、点把手、点杯口内壁，命中的都是同一个零件，结果就是**整只杯子（包括内壁和把手）全被贴上图案**。拆开之后才能做到：

- 点杯身 → 只有杯身外壁出现图案，把手和内壁保持原样；
- 面板上直接给出「可贴图部位」按钮，不用在 3D 模型上费劲找零件。

## 三、在 3ds Max 里怎么操作

> 菜单名各版本可能略有差异（本文按 2023+ 描述），括注了英文项名方便对照。

### 1. 导入混元导出的 GLB

**文件 → 导入 → 导入…（File → Import → Import…）**，选中混元的 `.glb`。

⚠️ 不要用「合并（Merge）」，那会把对象并进当前场景，残留在场的老对象容易一起被导出。

导入后先看一眼**面数**（右键 → 对象属性，或视图右上角的统计）。混元生成的模型面数通常很大，
如果 Max 卡得厉害，先加一个「**专业优化（ProOptimizer）**」减面到 30 万以内再拆 —— 面数只影响性能，不影响拆分。

### 2. 转成可编辑多边形

混元进来的是三角网格。选中对象 → 右键 → **转换为 → 可编辑多边形（Convert To → Editable Poly）**。

### 3. 选面 → 分离

1. 按 `4` 进入**多边形**子对象层级；
2. 选中要单独贴图的那些面（框选 / 环形选择 `Alt+点击边` 都好用）；
3. 展开右侧「**编辑几何体（Edit Geometry）**」卷展栏 → 点「**分离（Detach）**」；
4. 弹出「分离为」对话框，**「作为元素分离」不要勾选**（勾了会拆成一堆碎片），直接命名，例如 `cup_body`。

分完的部位会在场景里变成独立对象，原来的主体也要有名字。

> ⚠️ **这一步最容易犯的错：多选/漏选了面。**
> 典型症状是「点把手贴图，杯底也跟着变」，或者补 UV 时图案被挤到画面一角 ——
> 因为多出来的那块把包围盒撑大了。
> **最稳的做法是用「元素」层级选**：按 `5` 进入元素子对象层级，点一下把手，Max 会自动
> 全选整块连通的把手，不会漏。
> 分离动作做完后，**点一下分离出来的对象，看它是不是只剩你要的那一块**（Alt+Q 孤立显示很直观）。
> 拿不准就交给脚本：下面第 8 节讲了怎么**自动**把多选进来的一块拆出去，不用回 Max。

### 4. 命名

选中对象后，**修改面板（Modify）顶部的名称框**里改，或者按 `H` 打开列表改名。

格式是 `<商品前缀>_<部位>`：茶杯拆成两块就叫 `cup_body` 和 `cup_handle`。
完整规则、以及现成可用的整套名字，见第五节和第六节。

### 5. UV（可以交给脚本）

贴图靠的是模型自带的 UV 坐标，没有 UV 就完全贴不上去。两条路选一条：

- **省事**：跳过这步，导出后统一跑 `npm run models:fix`，它会按部位形状自动补 UV
  （回转体走柱面展开、片状的面走平面投影，接缝会拆点，不会留下拉伸条带）。
- **讲究**：给每个部位加「**UVW 展开（UVW Unwrap）**」修改器 —— 修改器列表 → UVW 展开 →
  打开 UV 编辑器 → 按形状挑投影方向（圆柱 / 平面 / 球形）→ **快速平面映射** → 把 UV 缩放到铺满 0–1 方格。
  `models:fix` 会识别到已有 UV 并原样保留。

判断标准：图案**均匀铺在这个部位上**，没有被拉成长条或挤成一团。

### 6. 给对象一个材质

选中每个部位 → 材质编辑器（按 `M`）→ 给它一个 **标准（Standard）材质**。

> 为什么必须给：**没有材质的对象会被 Max 导出成 `fallback Material`**，
> 颜色是纯黑、金属度/粗糙度是 glTF 的默认值 1 —— 渲染出来是一坨发暗的金属块。
> （`models:fix` 会把这个兜回来，但自己给上更省事。）
>
> 颜色给**白色**最好：网页端的「整体配色」会用拾色器里的颜色覆盖它，给白色改色最准。

### 7. 导出

**文件 → 导出 → 导出…（File → Export → Export…）** → 保存类型选 **glTF / GLB** → 默认设置直接导出。
只导商品本体，**场景里的灯光、相机、辅助对象先删掉或不要一起导出**。

> Max 的导出器会给每个对象套一层「外层 ×1000 / 内层 ×0.001」的父子节点。
> 这个不影响使用（`models:fix` 会把它烘焙掉），但别手动去删，容易把位置弄乱。

### 8. 有四种「选面特别难」的情况，可以不让 Max 干

手动刷选面在下面三种情况下几乎必错，脚本反而更稳（都是按几何算的，跑完可以用
体检页 `model-inspect.html` 分色看一眼确认）：

| 你要的效果 | 参数 | 原理 |
| --- | --- | --- |
| **把混进来的另一块面拆出去**<br>（例：拆把手时把杯底一起选进去了） | `--island-names "cup_handle=cup_bottom,cup_handle"` | 按**连通性**找：互不相连的面天然就是两块 |
| **把内壁单独拆出来**<br>（例：杯口内壁和杯身是连着的一整片，分不开） | `--extract-inner "cup_body=cup_inner"` | 按**法向**找：外壁法向背离杯轴、内壁法向指向杯轴 |
| **在「一整块光滑软体」上圈出一块可贴区**<br>（例：AI 直接出的帆布包，整个包是一个连通块、没有任何硬边） | `--extract-region "node_0=bag_front;axis=+z;cos=0.7;y=0~0.53"` | 按**朝向 + 包围盒归一化范围**：轴对齐半空间把面真正切开。**可以串联**，正反两面各圈一块。<br>★ **要「整圈外壁」时把 `cos` 设成 `-1`** —— `面法向·axis >= -1` 恒成立，朝向判定失效，这个开关就退化成**一把纯高度切刀**：直筒款茶杯 `mug_b` 的第一刀就是这样一刀切走「唇边 + 杯口」那一整段（切点是条直线，和用户红框压的线对齐）。⚠️ **多刀会连锁**，后一刀的 `y` 是相对「当前那块」的包围盒算的，改了前一刀就得重算 |
| **可贴区要严格贴合设计稿上画的框**<br>（例：`bag_b` 托特包只让面板正中那块矩形能印） | 同上，再多给 `x=` / `y=` 区间：`"node_0=bag_front;axis=+z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0.5~1"` | 用截图里的**包围盒当标尺量出区间**（见下一节的四步量法），不是试出来的 |
| **可贴区是「整个筒壁」**<br>（例：两只笔筒 `holder_a` 圆 / `holder_b` 方都只让筒身外壁能印，内腔和底都不能） | `--extract-inner "node_0=holder_inner"` + `--extract-region "node_0=holder_bottom;axis=-y;cos=0.7;y=0~0.06"` | 先用**法向**摘掉朝轴心的筒腔（连内底一起带走），再用**朝向**摘掉朝下的筒底，剩下就是外壁（见下面「笔筒」一节）。**方截面的体照用这一套** —— 判据是法向 / 朝向，与截面形状无关 |
| **模型自带一张烘焙好的贴图集**，要按「这块面在贴图里是什么颜色」分区<br>（例：团扇的白绢面 —— 整块 50000 面只有 1 个连通块，没有硬边也没有轴向，白绢和木框 / 竹柄全烤在同一张贴图上） | `--extract-by-color "node_0=fan_face;min=150;tol=16"` | 按**贴图颜色**找：取每个三角形 UV 重心处的颜色，要求「**中性浅色**」= 每通道 > `min` 且通道差 ≤ `tol`。木头是暖色、通道差 ≥ 40，圈不进来（详见下面「自带烘焙贴图的扫描件」一节） |
| 只是想让内壁**不贴图**，又不想拆 | —— | 拆开是唯一办法：贴图是整块 mesh 生效的，不拆就只能一起变 |

```bash
npm run models:fix -- "D:/.../文创商品模型/mug_a.glb" --out public/models/products/mug_a.glb \
  --island-names "cup_handle=cup_bottom,cup_handle" \
  --extract-inner "cup_body=cup_inner"
```

两个参数的取值都带一份**体检报告**（会先打印每块面的大小、朝里朝外的面数、估出来的内壁半径），
先加 `--dry` 跑一遍看清楚再落盘：

```bash
npm run models:fix -- "D:/.../mug_a.glb" --dry \
  --island-names "cup_handle=cup_bottom,cup_handle" --extract-inner "cup_body=cup_inner"
```

> `--island-names` 的名字是**按块从大到小**依次对应的（报告里的 1./2. 就是顺序），
> 所以杯子这种「杯底比把手还大」的情况也不会串。
> 名字的数量必须 ≥ 实际块数，少了脚本会直接报错而不是猜。

#### `--extract-region`：AI 出的软体模型怎么划「可贴区」

**什么时候用它**：混元 3D 这类 AI 直接生成的商品，整个模型往往是**一个连通块**，
而且相邻面的二面角全都很小（**一处硬边都没有**）。这时前两个开关都失效 ——
`--island-names` 只能找到 1 块，`--extract-inner` 找不到「轴线」。

参数格式 `<源零件>=<新名字>;键=值;键=值`：

| 键 | 含义 | 默认 |
| --- | --- | --- |
| `axis` | 主朝向：`+x` / `-x` / `+y` / `-y` / `+z` / `-z`（`+z` = 正对相机那面） | `+z` |
| `cos` | 法向与 `axis` 的夹角余弦**下限**（越大越只留「正对着」的面） | `0.7` |
| `x` / `y` / `z` | 该轴的**归一化区间**（`0` 是该轴最小端、`1` 是最大端），形如 `0.5~1` | 不切 |

再配一个 `--rename "<旧名>=<新名>"`，给**剩下那一块**（补集）改名：

```bash
# 帆布包 bag_a：正反两面都能贴（各圈一块），侧边/提手保留
npm run models:fix -- "文创商品模型/bag_a.glb" --out public/models/products/bag_a.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.7;y=0~0.53;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.7;y=0~0.53;z=0~0.5" \
  --rename "node_0=bag_body"
```

**这个开关可以串联用**：第二条规则**以第一条剩下的几何为输入**，所以「先圈正面、再从剩下的里圈背面」
一次运行就能做完。⚠️ 区间是**相对当次输入几何自己的包围盒**归一化的 —— 串联时第二条的 `x/y/z`
指的是「剩下那块」的包围盒，不一定是原始模型的。这里能直接写 `z=0~0.5`，
是因为「剩下那块」的 z 范围几乎和原始模型一致（补集里含了正面的内表面，把包围盒撑回去了）。

三个参数怎么估：

1. `y=0~0.53` 的上界是**袋口折边**的分界高度 —— 拿不准就先跑 `--dry`，报告里会按 y 分层
   打印「正面面积占比」，占比骤降的那一层就是折边（再往上就是提手）；
2. `z=0.5~1` / `z=0~0.5` 是**沿深度从中间切一刀**。模型是闭合壳体，正面外壁在 z 后半、法向朝 `+z`，
   背面外壁在 z 前半、法向朝 `-z`；两面各自的内表面朝向正好相反，会被 `cos` 和 `z` 区间同时挡掉。
   同时也避免「只按 `nz>0.7` 挑朝向时，C 形包在背面边缘外翻的那部分也被圈进来」（实测会多出 5 块）；
3. `cos` 从 `0.7` 往下调会把侧边也吃进来，往上调会漏掉褶皱处的面（打印出白斑），一般 `0.7~0.8` 合适。

> ⚠️ **「从背面看」的那块面要用镜像投影 `planar-z-back`**。
> 平面投影的 `u = (x - minX) / 跨度`，在观察点位于 -Z 时 X 轴在屏幕上**左右相反**，
> 沿用 `planar-z` 的话贴上去的文字、印章会**左右镜像**（正面看是对的、转到背面就反了）。
> `planar-z-back` 只翻 `u`、不动 `v`（上下与站在前面还是后面无关）。
> 投影表在 `scripts/fix-model.mjs` 的 `PROJECTION_BY_PART`，改表不用改代码。

> ⚠️ 三个实现上的坑（改 `fix-model.mjs` 时不要踩回去）：
> **① 边界要「切开」而不是「整块丢三角形」** —— 整块丢的话边界由三角形边决定，
> 屏幕上是一条约 4px 的锯齿（实测打印区上沿像被撕开）；按平面切开才是一条精确的直线。
> **② 裁剪必须做顶点去重** —— 原顶点按 `v<索引>`、交点按 `e<平面id>_<两个端点key>` 建表，
> 相邻三角形继续共用顶点；否则顶点数会撑成「三角形数 × 3」，文件体积大一倍多。
> **③ 补集要按凸块分解算** —— 「第 i 块 = 满足前 i 个平面、但落在第 i 个平面外侧」，
> 几块拼起来正好是盒外；**不能**把所有平面一起翻过来裁（那样得到的是「对面那个盒子」= 交集，
> 实测 50000 面的包只留下 22083 面，丢了一大半）。
> **④ 串联时主循环要优先取 `group.geometry`** —— 不能每次都退回读原始顶点 buffer，
> 否则第一条规则拆出来的那块会被丢掉。

#### 让可贴区**严格贴合设计稿上画的框**

设计稿（建模软件截图）上常有人手画的红框，要求「只对红框这块贴图」。**区间不要靠试，靠量**：

```bash
# 帆布包 bag_b：正反两面各一块矩形打印区（同一组区间）
npm run models:fix -- "文创商品模型/bag_b.glb" --out public/models/products/bag_b.glb \
  --extract-region "node_0=bag_front;axis=+z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0.5~1" \
  --extract-region "node_0=bag_back;axis=-z;cos=0.6;x=0.12~0.915;y=0.10~0.42;z=0~0.5" \
  --rename "node_0=bag_body"
```

量法四步：

1. **找一个已知长度的标尺** —— 截图里模型外面那圈**橙色包围盒**（建模软件选中物体时显示的框）
   通常就是世界包围盒。验证：量它的**像素宽高比**，与模型真实包围盒的宽高比对比。
   `bag_b` 是 `656/969 = 0.6770` vs `0.676/0.998 = 0.6774` —— 一致就说明能直接拿它当标尺；
2. 量红框四条边的像素坐标。⚠️ 要取**外沿**：描边本身有宽度（这次是 6px），
   取内沿会让打印区整体缩一圈；
3. 归一化（分母是橙框的宽/高，不是模型自己的）：
   `x_norm = (px - 橙框左) / 橙框宽`，
   `y_norm = (橙框下 - py) / 橙框高` —— **`y` 要上下翻转**，因为 glTF 的 y 朝上、图片的 y 朝下；
4. **用结果反验一遍**：拆完后 `bag_front` 的包围盒应该是
   `(x1-x0) × 模型宽` 与 `(y1-y0) × 模型高`。
   实测 `0.537 × 0.319`，而 `(0.915-0.12) × 0.676 = 0.5375`、`(0.42-0.10) × 0.998 = 0.3194` —— 对上了。

#### 可贴区是「整个筒壁 / 瓶壁」——把内腔和底整个摘掉（笔筒 ×2、花瓶 ×2）

两只笔筒都是 AI 直接出的一整块软体（各 50000 面 / 单个连通块 / 无 UV），
但要的不是「某一块矩形」，而是**「除了内腔以外全都算」**。
不能照搬帆布包那套朝向圈法 —— 外壁的法向是**绕一圈的各个方向**，
没有任何一个 `axis` 能圈住它。反过来做：**把不要的摘掉，剩下的就是要的**。

```bash
# 圆笔筒
npm run models:fix -- "文创商品模型/holder_a.glb" --out public/models/products/holder_a.glb \
  --extract-inner  "node_0=holder_inner" \
  --extract-region "node_0=holder_bottom;axis=-y;cos=0.7;y=0~0.06" \
  --rename "node_0=holder_side"

# 方笔筒 —— 同一条命令
npm run models:fix -- "文创商品模型/holder_b.glb" --out public/models/products/holder_b.glb \
  --extract-inner  "node_0=holder_inner" \
  --extract-region "node_0=holder_bottom;axis=-y;cos=0.7;y=0~0.06" \
  --rename "node_0=holder_side"

# 圆肚花瓶 / 细颈花瓶 —— 还是同一条命令，但底部区间要放大到 0~0.12（原因见下）
npm run models:fix -- "文创商品模型/vase_a.glb" --out public/models/products/vase_a.glb \
  --extract-inner  "node_0=vase_inner" \
  --extract-region "node_0=vase_bottom;axis=-y;cos=0.7;y=0~0.12" \
  --rename "node_0=vase_side"
```

实测结果：

| 模型 | 截面 | 内腔（含内底） | 筒底 / 瓶底 | 外壁（可贴） |
| --- | --- | --- | --- | --- |
| `holder_a` | 正圆（半径恒定 0.338） | 21394 面 | 3070 面 | 26646 面 |
| `holder_b` | 方带圆角（半径 0.319↔0.420 / 90°） | 21639 面 | 4419 面 | 24658 面 |
| `vase_a` | 正圆 | 2220 面 | 4644 面 | 43902 面 |
| `vase_b` | 正圆 | 3071 面 | 2987 面 | 44782 面 |

> **「回转外壁」不等于「必须是圆的」。** 判据是**法向与朝向**，跟截面形状无关，
> 所以方笔筒用同一套命令拆得同样干净：四个面法向朝 ±X/±Z、内腔面法向朝心
> （面心 `radialDot = −1`，到圆角处仍 < −0.707），`--extract-inner` 照样摘得掉；
> 口沿那圈方环是朝上的水平面（`ny > 0` 且半径 > 内壁半径），照旧留在外壁一侧。
> **先量一下截面再决定**：`npm run models:section -- holder_b` 会沿一圈扫半径 ——
> 各角恒定就是圆，每 90° 一个峰谷就是方（顺带能量出圆角半径：`r_max = (a−R)·√2 + R`，
> 实测 `holder_b` 的 R≈0.084 ≈ 半宽的 23%）。

两条规则各自解决一件事，**都不能省**：

| 步骤 | 摘掉什么 | 为什么不省 |
| --- | --- | --- |
| `--extract-inner` | 内壁**和**内底（朝上的水平面 + 半径小于内壁半径） | 筒腔和外壁是**沿筒口翻过去的一整片**，连通块分不开。不摘的话点外壁贴图时筒壁内侧一起变色，从筒口看进去很明显 |
| `--extract-region "axis=-y;cos=0.7;y=0~0.06"` | 朝下的筒底（只在最底下 6% 高度内） | 筒底的法向是 `-y`、`radialDot≈0`，`--extract-inner` 会把它判成「朝外」而留下。不摘的话它会被算进「侧面外壁」，用户点到看不见的底面也会贴上 |

⚠️ **筒口翻边故意留在 `holder_side` 里**，和茶杯把「杯口」算在 `cup_body` 一侧是同一个处理：
单独切出来的话，图案铺到筒口会突然断掉、在筒口留一圈**白边**。
`--extract-inner` 的水平面判定（`|ny| > 0.6` 且半径 > 内壁半径 → 算朝外）本来就把它留在外壁这边，
不用额外处理。

`--extract-region` 这里只用来**从剩下的几何里再抠掉一块**，`axis=-y` 配 `y=0~0.06`
（`y=0` 是最低端）。区间按**当次输入几何自己的包围盒**归一化，所以换模型不用改数字。

⚠️ **但花瓶不能照抄笔筒那个 `0.06`。** 花瓶的底是**两级**的 —— 外圈一圈朝下的环、加上
中心一块位置最低的底盘，两块几何上互不相连、分布在 5%~11% 高度这一段。`0.06` 那条切面
**正好落在它中间**，会把半个凹底留在可贴区里（症状：点外壁贴图，瓶底看不见的凹面也跟着被贴上）。
抬到 `0.12` 就整个摘干净。

**该取多少别猜，跑分层探针**：

```bash
npm run models:layers -- vase_a --layers 20      # 也可以直接喂 GLB 路径
```

它会把**每个零件**按高度分层，列出每层的「内向 / 外向 / 朝上 / 朝下↓ / 斜下」面数。
判读要点：底层那几层里还有多少「朝下↓」的面、这些面本该归谁 —— 一眼就能定出区间。
探针特意把「朝下」拆成两档（`朝下↓` = `ny ≤ −0.7`，就是 `--extract-region` 会摘走的那类；
`斜下` = −0.7 < `ny` < −0.6，是斜着往下的裙边，本来就属于侧壁）——
**不拆开的话，一眼扫过去会以为「可贴区里还残留着底面」，其实那是一圈正常的裙边。**

⚠️ **判「朝下↓ 那堆面该不该摘」，不能只看总中位半径 —— 要逐层跟同层的内 / 外壁半径比。**
探针现在除了总数，还会逐层打印「半径中位（同层 外壁 / 内壁）」。实测两个花瓶：

| 位置 | 面数 | 半径中位 | 同层外壁 | 同层内壁 | 结论 |
| --- | --- | --- | --- | --- | --- |
| `vase_a` 第 11 层（瓶口） | 1259 | 0.174 | 0.198 | 0.122 | 夹在内壁与外壁之间 → **外扩口沿的下表面**，属外壁，留着 |
| `vase_b` 第 11 层（瓶口） | 414 | 0.113 | 0.096 | 0.088 | 比外壁还大 → 同上 |
| `vase_a` 第 0~1 层（底部） | 41 | 0.254 | 0.244 | — | ≈ 外壁半径 → 壁底交界的倒角，属外壁 |

判断口径一句话：**半径比同层 `_inner` 的小，才是内壁翻边（该摘）；和同层外壁差不多或更大，就是外壁的一部分（留着）。**
误摘的代价是瓶口留一圈**白边** —— 和上面「筒口翻边故意留在 `holder_side` 里」是同一个道理。
另外，腰肩那些标着 `朝上` 的大批面（`vase_a` 第 7~9 层、`vase_b` 第 5~6 层）是**收颈处的上斜面**，
法向朝上但仍是外壁、照样可贴，**不是「盖」**。

> 花瓶还有一处和笔筒不同：**AI 生成的花瓶只建了从瓶口看得到的那一段内壁**
> （2000~3000 面、全长在瓶颈里、半径 0.05~0.14），腹部以内是**空的**。
> 这不是模型坏了 —— `--extract-inner` 摘出来的就是这一段，已经够用。

**`cos` 怎么定：对比几档阈值的面数，找「拐点」。** 面数随 `cos` 下降很快趋于平缓，
说明再放宽已经没有面可收（阈值够松了）；某个阈值以下突然掉一截，说明开始漏面（打印区会留白斑）。

| `cos` | 0.4 | 0.5 | 0.6 | 0.7 |
| --- | --- | --- | --- | --- |
| `bag_a`（软褶少） | — | — | — | 5822 面 ✅ |
| `bag_b`（软褶多） | 2999 | 2996 | 2968 ✅ | 2834 ❌ |

`bag_b` 在 0.6→0.7 之间掉了 134 面（拐点就在这儿），所以取 **0.6**；
`bag_a` 的面更平，`0.7` 就够。**不同料子要用不同阈值，别照抄。**

#### `--extract-by-color`：自带烘焙贴图的扫描件怎么分区

**先认清楚这类模型。** 前面几节讲的都是**白模**（没有贴图、靠网页端自己上色 / 贴图）。
但还有一类模型是**已经带着一张烘焙好的贴图集**来的 —— AI 上色件、扫描件都属于这类。
团扇 `fan_b.glb` 就是典型，它有四个「反常」特征：

* **整块 50000 面只有 1 个连通块**（`--island-names` 无从下手）；
* **一处硬边都没有、也没有明确的轴向**（`--extract-inner` / `--extract-region` 都失效）；
* **已经带 UV**，但那是**贴图集的 UV**（木纹、雕花边、白绢面全烤在同一张 4096² 图上）；
* 自带 baseColor / normal / metalRoughness 三张贴图，加起来 33 MB。

这种模型里「哪块面是白绢」**只能按贴图颜色认**：取每个三角形 **UV 重心**处的颜色，
要求它是**中性浅色** —— **每个通道都亮**（`min`）**且通道差小**（`tol`）：

```bash
--extract-by-color "node_0=fan_face;min=150;tol=16"
```

* **为什么不是「纯白」（`min=200`）**：白绢是**前后两层薄片**，被烘焙阴影压暗的那几层 `min`
  落在 150~200 之间。只圈外表面（实测 7353 面）的后果是 —— **扇子背面看不到正面的图案**，
  因为背面那层还贴着原来的贴图集。放宽到「中性浅色」能一次圈到 9097 面，正好是**两个完整的圆盘**。
* **为什么 `tol` 也得给**：木头是暖色，**通道差 ≥ 40**；白绢含阴影也在 16 以内。只卡 `min` 不卡
  `tol` 会把木框的亮部一起收进来。
* **采样点用三角形 UV 重心**：贴图集里各块之间是分开的 UV 岛，所以边界三角形不会骑在两种颜色
  中间 —— 分类天然是「按三角形」的，不会出现半块面。

⚠️ **阈值要逐点扫，并配一张目视分类图交叉验证。**
**不要只看两三个阈值就断言「平台」** —— 实测这个模型把 `min` 从 196 扫到 216 是**连续衰减**
（200→7353、205→1115、207→4），根本没有平台。当初就是只采了 200 与 210 两点，
误判成「平台在 200~210」，结果只圈到 1115 面。逐点扫出来真正稳定的那一段是
**`min` 120~180 都得到同一个 9097**（这个模型的中性色面要么很亮、要么就不中性，中间是空的）。

**这类模型还必须多做三件事**（都是 `models:fix` 的开关）：

| 开关 | 干什么 | 为什么非做不可 |
| --- | --- | --- |
| `--uv-force "fan_face"` | 只给「要当打印区」的那块**强制重算 UV**（平面展开） | 贴图集的 UV 撕不开，直接拿来贴图只会在四分之一角上一小块 |
| `--material "fan_body=keep"` | 其余零件**原样保留**材质（贴图 / 法线图 / metallic / roughness 一个都不动） | 那是模型自带的木纹，网页端一旦按调色板改色或套质感就没了 |
| `--material "fan_face=clean"` | 打印区那块**清掉所有贴图**、归到白坯 | 自带贴图（尤其法线图）会把用户上传的图案一起染上，而且法线图是按旧 UV 烘的，换成平面展开后完全对不上 |
| `--texture-size 1024` | 把内嵌贴图降采样（整数倍盒式平均）并重编码成 RGB PNG | 4096² × 3 张 = 33 MB，压到 1024 只剩约 2 MB（整个 GLB 3.2 MB） |

完整命令：

```bash
npm run models:fix -- "D:/.../文创商品模型/fan_b.glb" --out public/models/products/fan_b.glb \
  --extract-by-color "node_0=fan_face;min=150;tol=16" \
  --uv-force "fan_face" --material "fan_body=keep" --material "fan_face=clean" \
  --texture-size 1024 --rename "node_0=fan_body"
```

**网页端还要配合一件事**：`keep` 出来的零件在面板上要「连改色都不许改」。
这靠 `modelPresets.ts` 里的 `keepOriginalParts`（值写 `regions` 里的部位 id）：

```ts
keepOriginalParts: ['body'],      // 不套 finish / 不套调色板 / 不进全彩模式
partFinishes: { face: 'silk' },   // 按部位指定质感（团扇是白绢面 + 木框两种材质）
```

> **白绢是两层薄片、共用同一份 UV，所以贴上去的图案正反两面同时呈现** ——
> 用户要的「从背面看到正面图案的反向透影」就是这么来的，**不需要额外做半透明**。
> 前提是两层都在 `fan_face` 里（也就是上面 `min` 不能取太严）。
>
> 验证方法：`npm run e2e:paint -- --model fan_b --spin 180` —— 它会把商品转 180° 再拍一张，
> 两张图对着看就知道背面有没有跟着上色。

## 四、命名怎么才能被读到（关键，容易踩坑）

glTF 文件里**只有两种名字能存活下来**，其他命名方式一律会被丢掉。所以只有下面两条路：

### 方案 A：分离成独立对象（推荐）

在「可编辑多边形」的 `多边形`/`元素` 子对象层级选中要拆的面 → **分离（Detach）** → 对象名改成部位名。

导出后，three.js 读到的就是 `mesh.name`，直接等于你起的对象名。

### 方案 B：多维子材质（也可以用）

给面分配 **材质 ID**，每个 ID 对应一个子材质，**子材质名 = 部位名**。

导出后 three.js 会把一个多材质的 mesh 拆成 N 个 mesh，mesh 名会被导出器加上 `_1`/`_2` 后缀，但 `material.name` 原样保留 —— 程序两个名字都会查，所以照样能认出来。

### ✗ 这些命名方式一律无效

- **命名选择集 / 多边形选择集**（Selection Set）：glTF 规范里没有这个概念，导出必丢。
- **平滑组、图层、对象颜色、材质 ID 本身**：都不导出。
- **嵌套层级 / 组名**：3ds Max 的 glTF 导出器**会把层级拍平**，靠父对象分组来区分部位是不可靠的。

## 五、命名规则

**格式：`<商品前缀>_<部位>`，全小写，下划线连接，纯英文。**

| 商品 | 固定前缀 | 例子 |
| --- | --- | --- |
| 茶杯 | `cup_` | `cup_body`、`cup_handle`、`cup_inner`（直筒款没把手，`cup_handle` 可不出现） |
| 花瓶 | `vase_` | `vase_side` |
| 笔筒 | `holder_` | `holder_side`、`holder_inner`、`holder_bottom` |
| 帆布包 | `bag_` | `bag_front`、`bag_back`、`bag_body` |
| 扇子（团扇） | `fan_` | `fan_face`、`fan_body` |

三条硬规则：

1. **只用小写英文字母、数字、下划线。** 不要空格、点、斜杠、括号。
   - 中文名技术上能跑（程序做了 Unicode 归一化），但导出器和跨工具链容易出岔子，**建议不要用**。
2. **一个商品的所有部位用同一个前缀。** 不要 `cup_body` 配 `tea_handle` —— 前缀的作用是「一眼看出这个零件属于哪个商品」，混搭就失去意义了。
3. **同类商品共用前缀。** 两个茶杯都用 `cup_`：它们是分开导出的两个文件，不会重名，还能共用同一份配置。

### 前缀可以省，程序两种都认

不带前缀（`body`、`handle`）也能**精确**匹配 —— 配置表里每个部位都同时写了带前缀和不带前缀两个别名。

但还是**推荐带前缀**：一个 Max 场景里同时摆着几个商品时不会重名，导出后排查也快。你如果已经按 `tea_handle` / `cup_body` 这种风格命名了，只要同一商品前缀统一、用下划线分隔，一样认。

### 匹配是宽容的，但优先级明确

程序按四级优先级找名字，数字越小越可信（以配置里写 `cup_body` 为例）：

| 优先级 | 规则 | 命中例子 |
| --- | --- | --- |
| 1 | 完全一致（忽略大小写；空格、连字符等价于下划线） | `cup_body`、`cup body`、`cup-body` |
| 2 | 去掉导出器补的 `_1`/`_2` 后缀后一致 | `cup_body_1` |
| 3 | 去掉全部分隔符后一致 | `CupBody` |
| 4 | 部位名出现在名字的分词里 | `mug_a_body` |

一个部位一旦能以优先级 1 命中，就不会再用低优先级去吞别的零件，所以不会误伤。

| | `bag_body` | 侧边与提手 | ✗ 保留 |
| `bag_b.glb` | `bag_front` | 包的正面（**面板正中的矩形**，按设计稿红框量出来的） | ✅ 可贴 |
| | `bag_back` | 包的背面（同上矩形） | ✅ 可贴 |
| | `bag_body` | 侧边与提手 | ✗ 保留 |
| `fan_b.glb`（团扇，**自带烘焙贴图的扫描件**） | `fan_face` | 扇面（白绢，**前后两层都要圈进来**） | ✅ 可贴 |
| | `fan_body` | 扇框与竹柄（**整块保留模型自带材质**） | ✗ 保留 |

> 标了「✗ 保留」的几行都带 `optional: true`，**模型里没有这些零件也完全没问题** ——
> 只是「有的话就自动锁住不让贴」。所以最省事的做法其实是：**别拆内壁和杯底**，
> 让它们留在 `cup_body` 里，然后……不行，那样点杯身内壁也会一起贴。
> 内壁/杯底要不要单独拆，取决于你**要不要让它们不贴图**：
> 要 → 拆出来（第 8 节有一条命令）；不要 → 就留在主体里省事。

### 「可贴 / 保留」由你定，改一个词就换

上表的 ✅/✗ 只是**默认值**：

```ts
{ id: 'handle', name: '把手', match: ['cup_handle', 'handle'], paintable: true },
//                                                              ↑ 改成 false 就锁住这个部位
```

- `paintable: true` —— **可贴**：用户点它，贴图就落到这个部位（「点哪儿贴哪儿」）
- `paintable: false` —— **保留**：用户点它，会收到「这是保留部位」的提示，不会被贴上
- `optional: true` —— 模型里**可以没有**这个部位，自检不会报「缺部位」

**想让每个部位都能贴？** 把 `paintable` 全改成 `true` 就行 —— 这样最贴合「点哪儿贴哪儿」的直觉。

### 拆几个区由你决定

- 配置里写了、模型里没有 → 那行标上 `optional: true`，就不算问题（比如你只拆了「杯体 + 把手」，没拆杯口内壁）
- 模型里有、配置里没写 → 自检会提示「未归类零件」，把 `npm run models:regions` 的输出粘回配置表即可

### 想要「图案只出现在杯身正面一小块」怎么办

把杯身再多拆一刀，例如拆成 `cup_body_front` 和 `cup_body_back`，然后在配置表里加两行：

```ts
{ id: 'front', name: '正面打印区', match: ['cup_body_front'], paintable: true },
{ id: 'back',  name: '杯身背面',   match: ['cup_body_back'],  paintable: false },
```

**拆得越细，可贴图区域就越精确。** 拆到什么程度由你的设计决定，配置表跟着改就行。

> **但如果模型是混元 3D 直接出的「一整块软体」**（没有硬边、整个是一个连通块），
> 在 Max 里也刷不出干净的分界 —— 这种情况**不用回 Max**，
> 用 `models:fix --extract-region` 按「朝向 + 包围盒范围」让代码切（见第三节第 8 条）。
> `bag_a.glb`（帆布包·一片式）就是这么做的：**两条规则串联**，`bag_front` / `bag_back`
> 各是一块都可贴，侧边与提手留在 `bag_body` 保留。
> `bag_b.glb`（帆布包·托特）用的是同一套，但多给了 `x` / `y` 区间，
> 把可贴区收成**面板正中那块矩形**（拿设计稿红框量出来的，不是试出来的）。
> 想要「正反两面印不同的图」，只要它们各自是独立部位就行 —— 页面每贴一次都会新建一张贴图实例，
> 先贴的那面不会被后贴的顶掉。

## 七、导出前的检查清单

- [ ] 每个部位**要么**有 UV，**要么**导出后跑 `models:fix` 自动补（完全没有 UV 的零件点上去会提示「这个部位没有 UV 坐标」，并跳过）
- [ ] 材质用 **标准材质**，Base Color 设成白色（没给材质会导出成纯黑 + 全金属，给白色还能避免和左侧拾色器打架）
- [ ] 每个部位**只有一整块连着的面** —— 多选/漏选的碎块会让人「点 A 部位、B 部位也跟着变」
- [ ] 多维子材质里**不要留空槽**（Max 的 glTF 导出器遇到空槽会导出异常）
- [ ] 场景里的**灯光、相机、辅助对象**删掉或不要一起导出
- [ ] 单位不敏感（网页按**相机投影高度**自动等比缩放，让每个商品在画布上都占约 40% 高 —— 换商品时屏幕上大小一致），但建议统一成 1 单位 = 1 米附近
- [ ] 单文件控制在 **15 MB 以内**，否则首屏加载会明显变慢
- [ ] 导出：**文件 → 导出 → 导出…** → 保存类型选 **glTF / GLB** → 默认设置直接导出
- [ ] **Y 轴朝上**（Max 是 Z 轴朝上，导出器一般会自动转换，导出后如果模型躺倒告诉我，配置里能补旋转）

> 3ds Max 自带 glTF 导出器（2023 及以后版本内置，不需要装插件）。已知限制：层级会被拍平、嵌套多维子材质只支持两级、位图以外的贴图节点不支持、顶点色不导出。我们用不到这些特性，正常拆分导出没问题。

```bash
npm run models:fix -- "路径/mug_a.glb" --out public/models/products/mug_a.glb \
  --island-names "cup_handle=cup_bottom,cup_handle" \
  --extract-inner "cup_body=cup_inner"
```

2. 应该看到每个部位都是 `[精确匹配]`，并且 `models:fix` 没有报「互不相连的面」告警；
3. 刷新网页（`npm run dev:all` 起服务）：上传一张图，右侧工作台会多出**「可贴图部位」按钮**，点一下就直接贴，也可以直接在商品上点。

> **想确认「内壁真的没被贴上」**，不用只靠眼睛看 —— 跑 `npm run e2e:paint -- --model mug_a`，
> 它会自动上传一张图、贴到杯身和把手，然后**读回每个零件的真实材质**断言
> 「内壁和杯底没有贴图、颜色没被高亮污染」。茶杯当前 **17/17** 通过。

收尾再跑一次**全表回归**：


它把「每个商品都要过一遍」这件事变成一条命令（**加了新商品不用改它** —— 商品清单由各脚本

### 想肉眼确认「哪块面属于哪个部位」

开发时可以把体检页开出来（`npm run dev` 起来后访问）：

```
http://localhost:5173/model-inspect.html?file=models/products/mug_a.glb
```

它会把每个零件单独上色、单独渲染一屏，并贴上一张**坐标纸**——
横轴是 U、纵轴是 V，能一眼看出「这块面是哪个零件的」「UV 有没有被拉伸」。加 `?tex=0` 就只看分色。

### 名字和配置对不上怎么办（不用找开发改代码）

跑 `npm run models:regions`。它读每个模型里**真实的零件名**，生成能直接粘贴的配置：

```
【笔筒·圆】holder_a.glb —— 3 个 mesh / 3 个零件名
  实际零件名：holder_inner, holder_bottom, holder_side

  建议粘贴到 src/data/modelPresets.ts（替换现有的 HOLDER_REGIONS 定义）：

const HOLDER_REGIONS: RegionConfig[] = [
  { id: 'inner' , name: '筒口与内壁', match: ['holder_inner', 'inner'], paintable: false, optional: true },
  { id: 'bottom', name: '筒底'      , match: ['holder_bottom', 'bottom'], paintable: false, optional: true },
  { id: 'side'  , name: '筒身外壁'  , match: ['holder_side', 'side'], paintable: true },
]

【笔筒·方】holder_b.glb —— 3 个 mesh / 3 个零件名
  实际零件名：holder_inner, holder_bottom, holder_side
  零件与前面的【笔筒·圆】一致，共用 HOLDER_REGIONS —— 核对无误即可跳过。
```

> 同类商品「零件名一致」时脚本会直接说**共用哪个常量**，不用粘第二遍。
> 反过来，两个帆布包的零件名也一样，但源码里**引用的是两个不同的常量**
> （`BAG_A_REGIONS` / `BAG_REGIONS`）—— 脚本会各自对着**自己那条 `regions:` 引用**报常量名，
> 不会因为「文件里靠前的那个交集也一样大」就串位（那是它踩过的一个坑，见下）。

它按这三条规则填：

| 情况 | 处理 |
| --- | --- |
| 本商品已配过的零件名 | 沿用你写好的中文名和「可贴 / 保留」 |
| 别的商品配过的同名零件 | 也沿用，但注释里标出**来源**让你复核 |
| 全新出现的零件 | 标成 `TODO 中文名`，你只需要填中文名 |

> ⚠️ 为什么第二条要复核：**同名不等于同义**。`body` 在茶杯里是「杯身外壁（可贴）」，
> 在花瓶里是「瓶身（可贴）」，在帆布包里却是保留件（`bag_body` 侧边与提手）。
> 脚本优先用本商品的表，借用到别的商品的设置时会明确标出来。

输出的**常量名会自动沿用源码里现有的**（两个茶杯仍共用一个 `CUP_REGIONS`，不会拆成两个），
`match` 里的别名（`'holder_side'` / `'side'`）和 `optional` 标记也会一起沿用 ——
所以粘回去时连商品配置里 `regions:` 的引用都不用动，也不会把手写的兼容性弄丢。

脚本**只读不写**：它不碰 `modelPresets.ts`，粘贴这一步由你确认，顺便当一次人工复核。

如果模型还没导出、没法跑脚本，也可以直接在网页上看 —— 名字对不上时，工作台的
「可贴图部位」区会把**模型里的真实零件名**列出来。

## 九、什么时候才需要找开发

大多数情况你都能自己搞定。只有这几类需要动代码逻辑：

- 想在模型上做**部位改色**（不只是贴图）—— 配置表已预留 `defaultColor` / `colorMode: 'per-material'`；
- 模型**躺倒 / 尺寸异常**（导出时轴向或单位不对）—— 可以在配置里补 `rotation` / `scale`；
- 想要的交互形态变了（例如「一个部位叠多层贴图」「按部位切换材质」）—— 这属于新功能。

以上都不用先给我模型，先说需求即可。
