## 纹理烘焙 GLB 上线（第三轮网格颜色升级）

- 新管线 `tools/bake_texture.py`：盒式六面 UV 展开（每纹素一条盒面射线与网格求交，
  24M 纹素 → 7.27M 表面采样点）→ 32 机位（远景16+近景16）双线性采样 → GLB。
- 机位采集：`bake_views.mjs near`（近景 16 机位，distFactor 0.52/0.66），
  软渲染一帧 10~30s，必须用帧计数器同步截图（上轮踩过旧帧坑）。
- 查看器：`viewer.js loadMesh` 按扩展名分流，.glb 走 GLTFLoader（vendor 里已有）；
  KHR_materials_unlit → MeshBasicMaterial。`config.js` mesh.url = scene_mesh_tex.glb。
- 手写 GLB 导出的两个坑：
  1. JSON 块必须用**空格**补 4 字节对齐（\x00 会让 GLTFLoader 的 JSON.parse 报
     "Unexpected non-whitespace character after JSON"）；
  2. 索引 accessor 的 count 用 `len(二维数组)` 取到的是行数（面数）不是元素数，
     导致只画 1/3 的三角形——必须 `reshape(-1)` 后取 len。
- 烘焙质量坑与修法：
  1. 条带右侧图集空区是纯黑，mipmap 缩小时污染邻域 → 最后一列延拓；
  2. 树叶间隙 ~30% 纹素未命中（黑洞）被顶点 UV 采到 → 黑色等高线伪影 →
     迭代膨胀填色（32 轮）+ 条带均色兜底；
  3. 泼溅前景叶影光晕污染样本 → 掩码腐蚀 3px + 两遍采样（第二遍剔除与
     第一遍均值偏差 >0.22 的样本，注意 mean 的 0-255/0-1 量纲）。
- 验证：e2e 全过（3s 切换、300 万面、930ms 加载）；远景色差中位 9/765、
  黑环 0%；近景色差中位 67/765、黑环 6%（树冠内部不透明差异为主）。
- 覆盖率提升：bake_views.mjs 新增 `ground` 模式（12° 低仰角贴地环 8 机位，
  distFactor 0.72，拍崖壁/桥底），40 机位重烘焙后覆盖率 63.1% → 69.6%，
  远景色差中位 10/765 稳定，近景 62/765。脚本日志最后一行打印的 OUT 路径
  是旧变量（cosmetic），实际文件写在 bake_views_ground/，无碍。

     simple_knn.cu 头部补 `#include <cfloat>`（E 盘源码 + WSL 内都打了补丁）。
  3. 验证扩展要先 import torch 否则 libc10.so 找不到。
