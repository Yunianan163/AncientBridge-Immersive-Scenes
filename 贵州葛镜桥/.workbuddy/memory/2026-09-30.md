## 高斯泼溅模型网格化（点云 → 三角面片）

用户要求把 scene.ply（282 万高斯，仍以点/泼溅显示）变成有真实表面的网格模型。

**调研结论**（GitHub + 论文）：
- 高质量网格化 SOTA：SuGaR (CVPR'24)、2DGS (SIGGRAPH'24)、PGSR、GOF (2024)——
  **全部需要从源图像重训**，只吃最终 PLY 的场景用不上。
- 只吃已训练 PLY 的后处理路线：**3DGS-to-PC（arXiv:2501.07478，GitHub
  Lewis-Stuart-11/3DGS-to-PC）**——高斯→表面采样点→泊松重建→网格，与项目
  现有 tools/gs_to_mesh.py 的范式一致。

**本次实际执行**（`gs_to_mesh.py` 改进 + 运行）：
- 相机位姿 `_cam_centers_sfm.npy` 1378 个**全是 NaN**（上次会话解算失败遗留），
  法向朝相机定向不可用 → 新增兜底：Open3D `orient_normals_consistent_tangent_plane(k=15)`
  （MST 一致定向，66.5 万点 24 秒，效果可用）。
- 内存只有 15.3GB（可用 2.8GB）→ 新增 `--voxel 0.004` 体素降采样：278 万 → 66.5 万点。
- **Open3D 0.20 API 坑**：泊松在 `o3d.geometry.TriangleMesh.create_from_point_cloud_poisson`，
  不在 PointCloud 上（0.16+ 挂到 TriangleMesh）。
- 泊松 depth 10：102 万顶点 / 206 万面 → 密度裁剪 → QEM 简化到 150 万面，
  输出 `models/scene_mesh.ply`（54.9 MB，带顶点色）。
- 质量体检：高斯中心到网格距离 median 0.0016 单位（≈0.18 m）、p90 0.48 m（115 m/unit）。

**网页端**：viewer.js / config.js / ui.js 的网格模式（M 键、`button[data-act="mesh"]`）
上次已接好，本次只补了产物文件即生效。

**E2E 验证**（`tools/e2e_mesh_check.mjs`，无头 Edge + CDP）：
- 泼溅模式加载 → 点网格按钮 → mesh 模式 150 万面 → 切回泼溅，全部通过。
- 无头截图会因软件 WebGL 渲染 282 万点占死合成器而超时 → **截图前先
  `window.__viewer.stop()` 暂停渲染循环，截完再 start()**。
- CDP 必须连 `/json` 里的 **page target** WS，浏览器级 WS 不支持 Page.enable。
- `import.meta.url` 转路径必须用 `fileURLToPath`（中文路径 percent-encoding 坑）。

## 网格质量反馈与改进（用户近距离截图对比后）

用户反馈网格模式近看太差（植被成「蜡融感」大色块）。

**已做**：
- `--voxel 0.0035 --depth 11 --target-tris 3000000` 重生成 `scene_mesh_hd.ply`
  （111 MB，300 万面）；高斯→网格距离 median 0.0008（≈9 cm）、p90 0.0025，
  比 SD 版减半。**depth 11 只用了 2.5 分钟、没爆内存**（15.3GB 总内存可用 3GB 时也 OK）。
- 观感差还有一个被忽视的原因：网格用 MeshStandardMaterial 受光，被漫游角色的
  强灯（ambient 1.4 + key 2.4）照出过曝/假阴影，而泼溅是自发光。
  → viewer.js 支持 `mesh.unlit`，默认 MeshBasicMaterial 顶点色直出，观感立刻对齐
  （与泼溅同机位对比：共同模型区域色差中位 9/765）。
- config.js mesh.url 已指向 HD 版。

**结论（重要，写给以后的会话）**：
- 泊松网格**永远不可能**复现泼溅在植被上的观感——树叶是体积结构，面片无法表达。
- 网格的正确定位：碰撞/量测/导出其他软件；「看起来跟原来一样好」的需求
  本身就该用泼溅显示满足。
- 面片也要好看的正规路线 = 2DGS/PGSR 重训 + 纹理烘焙（需源视频 + COLMAP）；
  近景改善可做「泼溅渲染图投影烘焙纹理到网格」（下一步可做）。

## 顶点色烘焙已完成（第三轮）

**管线**：`tools/bake_views.mjs`（无头 Edge 驱动网页查看器，2 圈×8 方位=16 机位
泼溅渲染截图 + 相机矩阵导出）→ `tools/bake_vertex_colors.py`（顶点投影采样 +
embree 遮挡测试 + 夹角加权平均 + KDTree 邻域扩散补未覆盖顶点）
→ `models/scene_mesh_hd_baked.ply`（300 万面，111 MB），config.js 已指向它。

**踩的坑（重要）**：
1. **软渲染一帧 10~30 秒**，盲等固定秒数截到的是上一机位旧帧 → 颜色全部错位
   （第一轮烘焙全错）。解法：给 `viewer._tick` 挂计数器，轮询 `_bakeCount≥1`
   才截图。对位验证用「投影点 vs 画面非背景像素 IoU」+ 红点叠加目检。
2. **颜色量纲**：截图 0~255，Open3D 顶点色 0~1，漏除 255 被 clip 成纯白。
3. pip install scipy 被沙箱拦截（SIGTERM）→ 邻域扩散改用 Open3D KDTreeFlann。
4. 烘焙覆盖率 38.9%（相机环在场景上方，峡谷底部/背面天然采不到），
   其余顶点用 k=4 加权邻域扩散填充，最终全表面色彩一致。
5. 无头 Edge 截图整窗尺寸与 canvas client 一致（960×600），devicePixelRatio=1。

**效果**：顶点色变化 >0.1 的顶点占 60.5%；远机位下网格与泼溅色差中位 9/765；
近景受限于不透明实体（树冠挡视线是表示方式的本质差异，泼溅半透明可看穿）。

**近景对比机位选取教训**：closeup_check.mjs 盲选机位两次都落在树冠内部
（网格模式=绿墙）。给用户做演示截图时，机位要先在泼溅模式确认可见再切网格。
